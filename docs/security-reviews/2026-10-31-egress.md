## 1. Essence

augur's egress control is still a host-side, sudo-free, on-by-default domain allowlist. `augur-proxy` runs as the ordinary host user and re-checks every connection by hostname against a union-only, three-layer allowlist. It denies IP literals, connections without SNI, and private destinations. The guest has no direct route out. On Apple Container that means an `--internal` network with `--cap-drop NET_ADMIN` and `--no-dns`. On the macOS VM it means one host-owned NIC fed through gvproxy's `--socks-upstream`/`--dns-allowlist`/`--deny-direct`, now pinned to upstream `fecf420b`. It fails closed at every layer. An unreadable allowlist stops startup, an empty one denies everything, and an unreadable hot reload keeps the previous policy. A live self-test runs on every `up` path and tears the guest down if any direct probe gets out. This cycle left the proxy, allowlist, NIC and containment argv untouched and hardened what surrounds them. The Container self-test and the setup-token integrity gate now exec by absolute path, so a persisted guest cannot shadow them. augur refuses to attach to a running guest whose proxy or gvproxy cannot be shown to be the installed binary, with no override. The macOS admin password no longer rides any argv.

## 2. Enforcement boundary per engine

Both engines still share one merged allowlist and one `augur-proxy` filter core. `augur-proxy/` and `augur.conf` are byte-identical to the baseline (trees `96f96028…` and `62054fa6…`). What differs is how the guest is cut off from direct egress. Apple Container cuts it at the network layer: an `--internal` host-only network, no guest resolver, no `NET_ADMIN`, and a host proxy bound to that network's gateway. The macOS VM instead has one host-owned NIC socket fed through gvproxy. Both engines end in a live boot self-test that tears the guest down on a leak. The Container half changed in this window in ways the baseline does not describe: a proxy-binary freshness gate, a network-helper restart before each attach, and absolute-path self-test and integrity-gate programs. The argv that does the enforcing is still asserted by no test.

### 2.3 Container lifecycle: persist-and-reconcile

**The shape is unchanged: `down` stops and keeps, `destroy` removes, `up` reconciles.** `cmd_up` (`augur:2765-2802`) runs `require_engine_version` (`:368-378`), then `require_fresh_egress_helpers` (`:1058-1095`), then `ensure_image`. It then dispatches three ways:
1. **Running:** `reconcile_running_container` (`:2481-2496`). It re-runs the TOFU gate and a deliberately redundant `write_merged_allowlist` (`:2484-2488`), then refuses on fingerprint drift (`:2494`, `:2507-2512`), then runs `finish_up`.
2. **Stopped with a matching fingerprint:** reuse (`:2788-2799`). It runs `start_egress`, then `restart_egress_network_helper`, then `start_stopped_container`, which retries the start 3 times (`:2807-2813`). A persistent start failure falls through to recreate (`:2798`).
3. **Otherwise:** `recreate_container` (`:2516-2577`), with the argv built by `_add_egress_run_args`, `_add_state_mount_run_args` and `_add_host_config_run_args`.

All three converge on `finish_up` (`:2458-2478`), at `:2495`, `:2576` and `:2795`. `finish_up` runs `start_egress_proxy` then `verify_egress_locked` under `egress_enabled`, then `apply_guest_profile`. It is the only caller of the self-test (`:2461`).

**New since the baseline:**
1. **The stale-binary gate has landed.** The baseline listed it as in flight. `require_fresh_egress_helpers` refuses (exit 1, no override) to attach to a running container while its `augur-proxy` is not verified as the installed binary. It is called first in `cmd_up`, `cmd_claude`, `cmd_shell` and `cmd_setup_token` (`:2768`, `:2818`, `:2850`, `:2875`), and the macOS peers call it too (§2.4). It deliberately skips `down`, `destroy`, `status` and `list`, so they remain the way out. It is pinned by `tests/43_proxy_stale_binary.sh` (271 passed, 1 in-script skip: no `python3` for the macOS gvproxy stub). Mechanism and entry points are in the "What changed" section.
2. **The network helper is restarted before each attach.** `restart_egress_network_helper` (`:1686-1727`) is called before `run` (`:2557`) and before the reuse `start` (`:2793`). The bridge-unit collision it guards against is apple/container#2051. It skips when the network was created this run (`:1689`), when `launchctl` is absent, and when the container is running (`:1707`). The code says this check only narrows the race, and records concurrent runs for one project as an accepted trade-off (`:1702-1706`). ### 2.5 Workspace containment

**This guard applies identically to both engines, so it is written once here.** `require_safe_workspace()` (`augur:1367-1407`) refuses a workspace that is `/`, is `$HOME`, contains `$HOME`, or is, contains or lives inside `$AUGUR_DIR`. The rule is that the workspace is shared read-write into the guest, so a guest that can write `~/.augur` can replace the host-executed binaries and edit the merged allowlist. The refusal prints the resolved path and states `augur destroy` as a remedy for an older guest (`:1397-1405`, `exit 1` at `:1406`).

**Mechanics:**
- It compares physical paths. The workspace and `$HOME` are resolved with `cd … && pwd -P` (`:1369-1372`).
- `$AUGUR_DIR` is resolved through its parent, so a first run with no `~/.augur` still compares something (`:1376-1381`).
- The branches are `/` (`:1385`), `== $HOME` (`:1387`), `$HOME` inside the workspace (`:1389`) and the three `$AUGUR_DIR` relations (`:1391`).

### New this review

48. **[LOW–MEDIUM, assurance; same class and bound as item 46] A guest-writable `~/.curlrc` blinds the direct-egress probes, on both engines.**
    - The probes are `curl -s --max-time N -o /dev/null <url>` and read success as "leak": Container `augur:1787` (7 targets), macOS `:2080`. Neither passes `-q`, so curl reads `$HOME/.curlrc`. In Container mode `HOME` is `/home/dev`, which the persisted guest can write.
    - **Measured here (curl 8.5.0, same env shape as the probe: `HTTP_PROXY=`, `NO_PROXY='*'`, baked `no_proxy=localhost,127.0.0.1`, under `/bin/sh -c`).** A loopback target stood in for a leaking route.
      - With no config, `curl` exits **0**, which the self-test reads as a leak.
      - With `~/.curlrc` containing `proxy = "http://127.0.0.1:9"`, it exits **7**, so the self-test reads "isolated" while the route is open.
      - `curl -q` ignores the file.
    - macOS curl's `~/.curlrc` handling is documented curl behaviour but was not run here. The through-proxy probe cannot be forged this way: `-x` on the command line overrides the config, and a status needs a real responder.
    - The absolute `/bin/sh` and `PATH` pin of #215 do not touch config files.
    - **Why not higher:** this blinds *detection* on a reuse path. Enforcement (`--internal`/`--cap-drop`/`--no-dns` plus augur-proxy on Container; gvproxy's three flags on macOS) is host-side and independent.
    - Cheap fix: `curl -q` in every probe. Not filed.
49. **[LOW, hygiene; not an egress bypass] Helper liveness is `kill -0` on a pidfile pid, with no identity check, and the new replace path escalates to SIGKILL.**
    - `proxy_running` (`augur:925-930`) and `gvproxy_running` (`:1891-1896`) only test that the pid is alive.
    - `replace_stale_helper` → `terminate_and_wait` (`:289-298`, `:1024-1034`) now SIGTERMs and then SIGKILLs that pid when the sidecar says `changed` or `no-record`.
    - Pidfiles live in `~/.augur/proxy` and survive a reboot. If the recorded pid has been reused by an unrelated process of the same user, the replace path would kill it. `stop_proxy` has had the SIGTERM half of this exposure all along (`:1573-1577`).
    - Needs a stale pidfile, a reused pid and a non-fresh verdict together. Code-read only, not reproduced.
    - Cheap fix: compare `ps -o args= -p $pid` against the helper binary before signalling. Not filed.
50. **[LOW, accepted] The build-provisioning gvproxy is reused when stale, warn-only.**
    - `start_provision_gvproxy` (`augur:5192-5215`) warns and returns 0.
    - The reason is recorded in the code: the provisioning identity is fixed, not per-project, so a live one may be another build's NIC.
    - Scope: `augur build/update --macos` provisioning, not project VMs. The provisioning proxy, by contrast, is replaced.
    - Residual: a base-VM provisioning run can be served by an older gvproxy than the one installed, with the operator's own manifest and hook as the guest workload.
51. **[LOW / Info, accepted trade-off] The macOS guest's console lock is deliberately disabled.**
    - `configure_macos_guest_session` (`augur:3968`) writes `autoLoginUserScreenLocked=false`, `loginWindowIdleTime 0`, `pmset displaysleep 0 sleep 0` and `askForPassword 0`. It runs on every fresh boot (`:4212`) and in the base build (`:3452`).
    - The code states it relaxes the GUI lock only, with ssh, sudo and egress untouched.
    - Exposure: anyone at the host's `--gui` window gets an unlocked guest session. That is already the operator's own account, and the guest has no host reach beyond item 12.
    - Pinned by `tests/48_macos_guest_session.sh` (17/17).
52. **[LOW, availability] The shared-bridge guard (`restart_egress_network_helper`, `augur:1686`) is best-effort.**
    - It kickstarts the project's `com.apple.container.container-network-vmnet.<net>` launchd service before attach, on the create and the stopped→start paths (`:2557`, `:2793`), so Apple Container's shared bridge unit (apple/container#2051) is not reused by another project's live bridge.
    - Every failure only warns and returns 0: service not found, kickstart failed, or not running after 10 s.
    - Not covered, by the code's own comment: the default network used by `container build` and `--no-egress`, hand-made networks, and a second `augur` run attaching between the `container_running` check (`:1721`) and the kickstart. The code accepts that last race, since concurrent runs per project are unsupported.
    - Failure mode is closed. A collided project loses connectivity rather than gaining a route; the proxy rebind is untouched. Pinned by `tests/47` (25/25, `launchctl` shimmed). The real launchd behaviour was not exercised here.
53. **[LOW, inherent] Guest-controlled bytes still reach the operator's terminal raw on two channels `sanitize_guest_text` does not cover.**
    - The interactive `claude`/`shell` TTY (`eng exec -it`, `augur:2839`, `:2861`) is a passthrough by design. An agent can emit escape sequences, and whether OSC 52 sets the host clipboard depends on the operator's terminal.
    - `run_provision_manifest` echoes raw `brew install` output (`:5336`), and `hook.sh` output streams to the TTY. Both are operator-supplied inputs in the trusted base build.
    - Not measured live. The closed #155 covered augur's own status and error printing, not these.

No new residual comes from the `augur-proxy/`, `augur.conf` or `augur-vm/` trees: all three are byte-identical to the baseline. The destroy-by-name and completion work adds no residual (see the refuted entries above). Items 46 and 47's macOS halves, 24, 32, 48 and the `~/.curlrc` route are the open assurance debt that this range's changes did not touch.

### Summary

This cycle is net-positive for the residual-risk posture. The largest closures are two items the 2026-09-24 review recorded as open: the macOS admin password is off `ssh` argv (item 44, PR #217) and the Container-mode self-test and setup-token gate no longer look up programs through the guest-writable `PATH` (items 46 and 47, Container halves, PR #215, mutation-checked offline). PR #202 stops a running guest being served by a replaced `augur-proxy` or `augur-gvproxy`. The gvproxy pin moved six times to `fecf420b`. Against a fresh upstream clone the patch applies cleanly and every gate (SOCKS dial, DNS allowlist ahead of the type switch, UDP/ICMP and gateway-mux skipped under `--deny-direct`) is still in place, though no Go build or `go test` ran here. The pin is 2 deps-only commits behind upstream `main`; the freshness check reports `REVIEW`.

The core filter is untouched: `augur-proxy/`, `augur.conf` and `augur-vm/` are tree-identical to the baseline, with 54/54 Swift tests and the live proxy tiers 23, 24 and 25 green against a debug build. Offline suite: 1318 passed, 0 failed (1348 with the debug proxy binary).

One genuinely new finding came out of this pass (item 48). A guest-writable `~/.curlrc` can still make a leaking route read as isolated, even after the absolute-path fix. It blinds detection only, and `curl -q` fixes it. Items 49–53 are small hygiene, availability and accepted-trade-off notes, none of them an egress bypass.

The standing assurance gaps are unchanged. The macOS halves of items 46 and 47 have no cheap in-guest fix, because the ssh transport runs through a guest startup file. Item 24 (unguarded reconcile-path self-test) is still open. Item 32 is still the largest gap, with four mutants staying green, though I1's "no offline peer" wording is now slightly too strong. The unchanged boundary is the host-side `--internal`/`--cap-drop`/`--no-dns`/augur-proxy stack on Container and gvproxy's three flags on macOS. As in every prior review, no live container engine or macOS guest ran here.
