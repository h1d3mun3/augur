## What changed since the 2026-07-10 snapshot

2026-07-10). 13 commits touched the egress core (`augur`, `augur-proxy/`, `gvproxy/`,

- **Fixed — SOCKS deny-path log-injection (`b50e176`, #37).** `DecisionLog.deny()`/`allow()`
  string-interpolated `host` verbatim. The SOCKS `atyp=0x03` domain destination reaches the deny
  path **unvalidated** (that's *why* it's denied — `Allowlist.allows()`/`isValidHostname` reject
  it for the allow/deny decision, but the raw bytes still hit the log sink either way). A crafted
  domain containing CR/LF could forge or split lines in the append-only decision log — the
  forensic record a user greps to decide what to allowlist. Fixed by `DecisionLog.sanitize(_:)`
  (`Logger.swift:63-80`), which escapes C0 controls/DEL (and `\` itself, first) before `host`
  reaches `allow()`/`deny()`. New regression test confirms an injected CRLF payload stays
  confined to one log line. **Does not touch I1–I8** — the allow/deny decision was always safe;
  only the *record* of a deny was forgeable.
- **Fixed — connection-cap slot leak (`daea806`/`1a00745`, #36).** `--max-connections` /
  `AUGUR_PROXY_MAX_CONNECTIONS` (default 128) is now backed by a real `DispatchSemaphore`
  (`connectionCap`, `ProxyServer.swift:25,36`), closing a leak where a failed
  `Thread.detachNewThread` in the splice layer's reverse-direction copier silently no-op'd under
  thread-ceiling pressure, hung the handler forever, and never released its slot — deadlocking
  the accept loop one layer below the cap meant to prevent exactly that. Now uses the checked
  `PosixThread.spawnDetached`; a spawn failure drops the tunnel cleanly instead of hanging. A new
  `InFlightGauge` adds hysteresis-gated, stderr-only capacity logging on a channel kept separate
  from the greppable DENY file. Covered by `tests/24_proxy_concurrency.sh` (real-binary tier, now
  wired into CI's `build-unit` job). **Residual, not closed by this fix:** no idle timeout on an
  already-established tunnel — a guest can hold a connection open-and-idle to pin a
  `connectionCap` slot indefinitely. Bounded (capped at `--max-connections`, no thread/FD
  exhaustion — far weaker than the original unbounded growth) and split off as a fresh, narrower
  issue: **#36 is closed; the idle-timeout residual is now tracked as #101.**
- **Closed by decision, not code — the exfiltration ceiling (`7090798`, ADR-0008, #24).**
  [`docs/decisions/0008-exfiltration-ceiling-accepted.md`](../decisions/0008-exfiltration-ceiling-accepted.md)
  formally accepts that an allowlisted, credentialed host (e.g. `github.com` + `GH_TOKEN`)
  remains an in-policy exfil channel, and declines to mitigate it — not just heavy options (TLS
  MITM/DLP, per-service authorization), but also the lighter opt-in middle ground previously
  floated (`--no-token`, a read-only-workspace mount). Rationale: closing this needs a
  fundamentally heavier class of control than a lightweight, sudo-free proxy should carry, and
  even a full build-out only buys post-hoc detection — weaker than the allowlist's existing
  unconditional "can't reach it at all" guarantee. This upgrades §6 item 1 below from "an open
  design question" to a permanent, closed decision. Issue #24 is closed.

  CA in the guest (container: baked via a `Dockerfile` build-arg; macOS: GUI-prompted keychain

## 1. Essence

augur egress control is a **host-side, fail-closed, on-by-default domain allowlist** that
confines a possibly prompt-injected coding agent (Claude Code today), running on a trusted
single-user host, by forcing *all* guest outbound traffic through **augur-proxy** — a
dependency-free Swift forward proxy that runs as the ordinary host user **with no sudo**. The
guest is severed from direct egress and its only route out is the proxy, which re-resolves each
connection **by hostname** and admits it only if it matches a **union-only, three-layer domain
allowlist** (managed baseline + user-global + per-project); everything else is denied and logged.
Egress is on by default (`AUGUR_EGRESS=auto`), unrecognized values fail *on*, and the same
allowlist/enforcement contract is shared across both engines. The design principle is
**containment, not exfiltration-proofing**: keep an untrusted agent away from arbitrary internet
endpoints and off the host, using only mechanisms that never require elevated privilege — and, as
of this snapshot, that principle is now a formally closed decision
([ADR-0008](../decisions/0008-exfiltration-ceiling-accepted.md)), not just review-doc prose. The
same fail-closed proxy/allowlist/TOFU machinery is also extended one layer earlier in the
lifecycle — to **building the shared base images** (§2.1) and, new this snapshot, to **trusting an
operator-supplied CA** (§2.2) — under mechanisms that cannot touch or widen any live project's
allowlist.

differ only in **where the proxy runs** and **how the guest is severed from direct egress**. All
five Apple Container enforcement elements and all macOS VM elements below were individually
re-verified against current code this snapshot; substance is unchanged from 2026-07-10.

### 2.1 Base-image custom provisioning (PR #78, unchanged)

An operator can pre-install extra packages into augur's *shared* base images at build time: a
Homebrew manifest for the macOS base VM (`~/.augur/provision/manifest.conf` + optional
`hook.sh`/`hook.allowlist.conf`) or an apt manifest for the Apple Container image
(`~/.augur/provision/container-packages.conf`). Both manifests are TOFU-gated (`tofu_decide`,
cache at `~/.augur/provision-hashes/`, separate from the per-project `~/.augur/project-hashes/`).
Inherits I1–I9 by construction. Its one new-in-kind residual (`hook.sh` is TOFU-gated executable
root content cloned into every VM) is unchanged — §6 item 11.

### 2.2 Custom CA trust (`augur install-cert`, new this snapshot)

A per-project operator command (PRs #88/#90, commits `9970c86`/`237ca47`) that trusts a single
operator-supplied PEM CA in the guest: on Apple Container it rebuilds the image with
`AUGUR_CA_CERT_B64` baked in (`Dockerfile`, `update-ca-certificates` run as root at build time,
then dropped back to the unprivileged `dev` user); on macOS it prompts a GUI keychain-trust
dialog over SSH — which is **manual-first on macOS 26**, since SSH-invoked keychain trust is
unconditionally denied there without a GUI session (`237ca47` fixes what was previously a silent
failure into an authoritative "do it yourself, here's how" instruction). Gated by an explicit,
per-invocation `y/N` (`AUGUR_ACCEPT_CERT_INSTALL=1` non-interactive override) — a one-shot
operator action, not the persisted-hash TOFU model §2.1 uses, since a CA is an explicit command
argument, not an auto-detected repo input. **Does not widen the egress boundary or the proxy's
trust model**: `augur-proxy` never terminates TLS (grep-clean of `SSLContext`/`SecTrust`/X509
verification across `Sources/`), so a guest-trusted CA only affects what the guest's *own* TLS
clients accept post-tunnel — the proxy's by-hostname allow/deny decision happens before that and
is unaffected.

## 3. augur-proxy filter internals (2 logic changes since 2026-07-10)

Same two-listener architecture — HTTP CONNECT (Apple Container) + SOCKS5 (macOS VM) over one
shared `Filter`; a blind TCP tunnel, decision by hostname, never TLS-terminating. Re-verified
against current code:

- **Fail-closed startup** (`main.swift:97-103`) — unchanged: dies if `--allowlist` is empty, dies
  if neither `--http-port`/`--socks-port` is set, `exit(2)` if `Allowlist.fromFile` returns nil.
  `publicOnly=true` by default (`main.swift:29`); only `--allow-private` clears it
  (`main.swift:57`) and remains grep-clean on every production path repo-wide (I1/I8).
- **Boundary-anchored matching** (`Allowlist.swift:59-88`) and **hostname validation**
  (`Hostname.swift:11-33`) — unchanged: `isSubdomain` still requires a label-boundary dot,
  `isValidHostname` still strict LDH / ≤253 total / ≤63 per label (I2, I3).
- **IP-literal deny + dead `PinTable`** (`Filter.swift:39-56`, `PinTable.swift`) — unchanged:
  `grep -rn "pins.pin(" augur-proxy/Sources` is still zero hits; every IP-literal connect denies
  unconditionally (I4).
- **SNI re-decide + re-dial by name** (`ProxyServer.swift:141-162`) — unchanged: SOCKS5
  IP-literal destinations are peeked for TLS SNI / HTTP Host, re-decided, and re-dialed by the
  peeked name; no recoverable name → `deny("no-sni")`.
- **Dial-time SSRF guard** (`SocketIO.swift:202-219`, `AddressPolicy.swift:13-47`) — unchanged:
  under `publicOnly`, skips RFC1918/loopback/CGNAT/link-local incl. `169.254.169.254`/
  IPv4-mapped/NAT64/ULA/multicast; unknown family refused (I8).
- **Hot reload** (`main.swift:139-169`, `Filter.swift:28-31`) — unchanged: 2 s mtime poll, atomic
  swap under lock, unreadable file keeps the previous policy (I6).

**Changed — deny logging (`Logger.swift`), commit `b50e176` (#37).** `DecisionLog.deny()`/
`allow()` previously string-interpolated `host` verbatim into the log. The SOCKS `atyp=0x03`
domain destination reaches `deny()` unvalidated (`ProxyServer.swift:164-171`) — that's *why* it's
denied — so a crafted domain containing CR/LF could forge or split lines in the append-only
decision log. Fixed by `DecisionLog.sanitize(_:)` (`Logger.swift:63-80`): walks Unicode scalars,
escapes `\` first (so its own `\xNN` markers can't be reinterpreted as attacker escapes), then
escapes every C0 control and DEL as `\xNN`. Both `allow()` and `deny()` route `host` through it.
A new regression test proves an injected CRLF payload stays confined to a single log line.
**I1–I8 unaffected** — the allow/deny decision was never wrong; only the deny *record* was
forgeable.

**Changed — connection-cap hardening (`ProxyServer.swift`), commits `daea806`/`1a00745` (#36).**
`--max-connections`/`AUGUR_PROXY_MAX_CONNECTIONS` (default 128, `main.swift:33`) is now backed by
a `DispatchSemaphore` `connectionCap` (`ProxyServer.swift:25,36`): the accept loop `wait()`s for a
slot before spawning a handler; the handler releases it via `defer` (`ProxyServer.swift:56-72`).
This closes a slot leak in `spliceBoth`: the reverse-direction copier was previously spawned with
the unchecked `Thread.detachNewThread`, which silently no-ops under `pthread_create` EAGAIN
(thread-ceiling pressure) — the handler then blocks forever and its slot never frees, deadlocking
the accept loop one layer below the cap meant to prevent exactly that. Now uses the checked
`PosixThread.spawnDetached`; on failure it drops the tunnel cleanly instead of hanging
(`ProxyServer.swift:263-266`). A new `InFlightGauge` (`ProxyServer.swift:303-340`) adds
hysteresis-gated, stderr-only capacity/recovery logging via a new `DecisionLog.status()` channel,
kept off the greppable DENY file by design. Covered by `tests/24_proxy_concurrency.sh` (real
binary, N≫cap simultaneous connections all served, gauge lines assert, DENY file stays clean;
wired into CI's `build-unit` job). **Documented residual, not closed by this fix:** no idle
timeout on an already-established (spliced) tunnel — a guest holding a connection open-and-idle
can still pin a `connectionCap` slot indefinitely. Bounded (capped by `--max-connections`, no
thread/FD exhaustion — far weaker than the original unbounded growth), explicitly deferred out
of #36's scope; **#36 is closed and the residual is tracked separately as issue #101.**

**Test results this snapshot**: `swift test` — **39/39 passed, 0 failures** (up from 38/38 on
2026-07-10). No I1–I8 invariant weakened by either change.

## 4. Three-layer allowlist config model + TOFU (unchanged)

Union-only merge — each layer can *widen*, none removes a lower layer's entries:

1. **Managed baseline** `~/.augur/augur.conf.default` — copied verbatim from repo `augur.conf`
   on every install.
2. **User global** `~/.augur/augur.conf` — scaffolded once, never clobbered.
3. **Per-project** `./.augur/allowlist.conf` — merged **sanitized only** (via
   `project_conf_domains` / `conf_line_valid`).

`write_merged_allowlist` (`augur:603-615`) cats baseline + global verbatim, appends only
sanitized project domains, and writes to `~/.augur/proxy/<slug>.allowlist` **outside the project
mount** — so a root-in-guest editing the mounted `./.augur/allowlist.conf` cannot widen its own
policy mid-session (I7). TOFU approval (`check_project_conf_approved`, `augur:818-863`)
fingerprints the project conf (fails closed if no hash tool), prints sanitized widening domains +
prompts `[y/N]`, and stores approvals host-side keyed on the full workspace path.

## 6. Known limitations & residual exfil channels

The threat model is *"contain a prompt-injected agent away from its host,"* **not** *prevent
exfil through a legitimately allowlisted, credentialed host*.

1. **Allowlisted + credentialed host is an in-policy exfil surface — now a closed, permanent
   decision.** `github.com` is allowlisted and a full-scope `GH_TOKEN` is injected → an injected
   agent can push data to an attacker repo entirely within policy. As of this snapshot,
   [ADR-0008](../decisions/0008-exfiltration-ceiling-accepted.md) formally closes the design
   question this used to be (GitHub issue #24, closed): augur will not mitigate this, by default
   or opt-in — not TLS MITM/DLP, not per-service authorization, and not the lighter
   `--no-token`/read-only-mount middle ground either. Users who need this belong on dedicated
   security tooling (DLP/CASB/enterprise egress proxy) alongside augur, not inside it.
2. **Wildcard / QNAME tunneling.** A broad wildcard (e.g. `*.githubusercontent.com`) permits
   `<data>.<wildcard>` leakage; mitigation is allowlist policy, not the matcher.
3. **Apple Container `0.0.0.0` host-reach (accepted trade-off).** Host-only `--internal` lets
   the guest reach other host services bound to `0.0.0.0` — weaker than an isolated network. A
   direct consequence of the no-sudo constraint (closing it needs host `pf` = sudo); documented,
   not enforced, effectively **permanent**. Now the load-bearing example in
   [ADR-0001](../decisions/0001-sudo-free.md), which also records that an `augur up` warning for
   this was prototyped, measured, and declined (dominated by non-actionable system daemons).
4. **No-sudo consequences ripple through the datapath.** "Never require sudo" took priority over
   stronger isolation, forcing host-only + host-side proxy (Apple) and `VZFileHandle` + gvproxy
   SOCKS (VM). Provisioning and `install-cert` (§2.2) extend the same principle rather than
   relaxing it.
5. **TOFU auto-accept widens non-interactively.** `AUGUR_ACCEPT_PROJECT_CONF=1` /
   `AUGUR_ACCEPT_PROVISION_HOOK=1` / `AUGUR_ACCEPT_CERT_INSTALL=1` widen without operator review
   (used by CI / non-interactive runs).
6. **Credentials on Apple Container `container run -e` argv (M1).** `ANTHROPIC_API_KEY` /
   `CLAUDE_CODE_OAUTH_TOKEN` / `GH_TOKEN` are visible to a co-resident host process via
   `ps`/`/proc`. Accepted Low under the single-user premise; **resurfaces on a shared host**.
   (macOS writes them to `~/.augur-env` chmod 600 via SSH stdin, never on argv — a design choice
   [ADR-0007](../decisions/0007-macos-build-fixed-credential.md) reinforces the rationale for.)
7. **Basename-only slug collisions (~1/900).** Approval-hash and history dirs are full-path-keyed,
   but container/VM names and egress ports/subnet remain basename-keyed, so two same-basename
   projects running concurrently collide on ports/subnet; recovery is a manual override.
8. **Every "accepted" residual assumes a single-user host.** On a shared host / CI runner, the
   argv secret exposure, name collisions, and cross-tenant reach all resurface.
9. **Fail-closed edges are hard errors, not graceful.** Proxy readiness is a fixed ~2 s poll and
   gateway-iface readiness waits ≤5 s; on slow bring-up the bind can fail and `exit 1`.
10. **Compatibility limits (fail-closed).** No-SNI (ECH/ESNI, non-TLS/non-HTTP) and IPv6/IP-
    literal connects are denied. augur's needs are all HTTPS, so this is accepted.
11. **hook.sh is TOFU-gated *executable root content*, not a data file.** `run_provision_hook`
    runs an arbitrary root script (`sudo bash …`) once approved; its blast radius is every VM
    cloned from the base image. Unchanged.
12. **[HIGH — inherent to the model] RW workspace mount → host code execution via `.git/hooks` —
    now documented in the README, code/architecture unchanged.** `WORKSPACE_DIR=$(pwd)` is
    bind-mounted **read-write** into the guest. A prompt-injected guest can plant
    `.git/hooks/pre-commit` (or similar); the next **host**-side `git` operation in that repo
    executes guest-authored code at the user's full host privilege — a complete escape of both
    the container/VM boundary and the egress allowlist. Inherent to augur's core model; mitigation
    remains entirely out-of-band (review diffs, treat `.git/hooks` as attacker-controlled).
    **New:** `README.md` now carries this exact warning in both engines' "File access" sections
    (commit `645bf60`) — previously it lived only in this review ledger.
13. **[LOW, fixed] macOS `~/.augur-env` secret interpolation validated.** `validate_secret_value`
    (`augur:303`) now rejects shell-metacharacter/control-byte secrets before the
    `~/.augur-env` write. *Fixed in PR #84 (F2), confirmed present this snapshot.*
14. **[LOW, fixed] `resources.conf` values clamped.** `MEMORY`/`MACOS_CPU`/`MACOS_MEMORY_MB` are
    bounds-checked, including a 64-bit-multiply-overflow follow-up (`7a7bfaa`) that closed a
    bypass where a value like `MEMORY=17179869185g` wrapped past the ceiling. *Fixed in PR #84
    (F4), confirmed present this snapshot.*
15. **[Superseded by a stronger fix] Whole `~/.claude.json` scp on macOS.** The 2026-07-10
    snapshot recorded this as "Fixed in PR #84 (F3)" via jq-stripping `mcpServers`/`projects`
    before scp. As of `3d59f7d` (#90), the fix is **stronger**: the real file is never read or
    copied at all — a static onboarding stub is seeded instead (§2, "What changed"). No residual.
16. **[LOW, fixed] `verify_egress_locked` IPv6-literal probe added.** *Fixed in PR #84 (F5),
    confirmed present this snapshot* (not independently re-verified this pass beyond confirming
    the commit is an ancestor of HEAD).
17. **[LOW] Apple Container proxy opens both listeners.** Unchanged — in container mode the proxy
    binds the guest-facing gateway and opens both HTTP and SOCKS listeners though only HTTP is
    used. Avoidable surface, not a bypass. *Still deferred.*
18. **[LOW — hygiene] macOS base-VM sudo-revoke is branch-coordinated and untested.** Unchanged.
    *Still deferred.*

### New this review

19. **[LOW] No idle timeout on established (spliced) tunnels.** Split off from #36 when its
    connection-cap fix landed (§3): a guest can hold an already-established tunnel open-and-idle
    indefinitely, pinning up to `--max-connections` slots and denying service to *new*
    connections once the cap is reached. Bounded by the semaphore (no thread/FD exhaustion, no
    return to the original unbounded-growth DoS) — a materially weaker residual than what #36
    originally tracked. Needs a shared-activity timer (reset on any byte transferred in either
    direction), not a naive fixed read-deadline, to avoid mis-cutting legitimate long-lived
    low-traffic connections (SSE, long-polling). Tracked as **issue #101**; not yet implemented.

### Summary
Egress control is unchanged in shape since 2026-07-10 — a **host-side, fail-closed, sudo-free
domain-allowlist scheme shared by two engines** (Apple Container + macOS VM), on by default, with
a union-only three-layer merge, TOFU approval, and a Swift filter core — all **re-verified green
(39/39 Swift, 170/170 shell assertions incl. 29/29 for I7, structural macOS-VM checks)** on
2026-07-20. Two logic changes landed in the proxy core: a **decision-log CRLF-injection fix**
(#37) and a **connection-cap slot-leak fix** (#36, its one residual — no idle-timeout — split
into new issue #101). A new opt-in feature, **`install-cert`**, was confirmed inert to the egress
boundary. The macOS `~/.claude.json` file-exposure channel this ledger tracked is now closed by
construction, not filtering. Two prior open design questions are now closed by formal decision
records rather than left as review-doc prose: the **exfiltration ceiling** (ADR-0008, permanent,
declines even opt-in mitigations) and, reinforcing rather than newly closing, the **sudo-free
principle** (ADR-0001) and the **fixed macOS credential** (ADR-0007). The **RW-workspace
`.git/hooks` host-code-execution path** (§6 item 12) — still the single highest-impact residual —
is unchanged in the code but is now documented where a user will actually see it (the README),
not only here. No invariant (I1–I10) changed status this snapshot.
