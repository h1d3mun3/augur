## 1. Essence

augur egress control is a **host-side, fail-closed, on-by-default domain allowlist** that confines a possibly prompt-injected coding agent (Claude Code today), running on a trusted single-user host, by forcing *all* guest outbound traffic through **augur-proxy** — a dependency-free Swift forward proxy that runs as the ordinary host user **with no sudo**. The guest is placed on an `--internal` network with `NET_ADMIN` dropped and external DNS killed, so its only route out is the proxy, which re-resolves each connection **by hostname** and admits it only if it matches a **union-only, three-layer domain allowlist** (managed baseline + user-global + per-project); everything else is denied and logged. Egress is on by default (`AUGUR_EGRESS=auto`), unrecognized values fail *on*, and the same allowlist/enforcement contract is shared across all three engines. The core design principle is **containment, not exfiltration-proofing**: keep an untrusted agent away from arbitrary internet endpoints and off the host, using only mechanisms that never require elevated privilege.

As of this snapshot, that same fail-closed proxy/allowlist/TOFU machinery has also been extended one layer earlier in the lifecycle — to **building the shared base images themselves** (§2.1) — under an independent, dedicated proxy identity so it never touches, and cannot widen, any live project's allowlist.

## 2. Enforcement boundary per engine

All three engines share the *same* merged allowlist and the *same* augur-proxy filter core; they differ only in **where the proxy runs** and **how the guest is severed from direct egress**.

| Engine | Proxy placement | Guest containment | Strength | Specific weakness |
|---|---|---|---|---|
| **Docker (sidecar)** | augur-proxy runs as a **dual-homed Linux sidecar container**: fixed `--ip` on a per-project `--internal` network + joined to `bridge` for its own egress | Agent on per-project `--internal` net (no host/internet route), `--cap-drop NET_ADMIN`, `HTTP(S)_PROXY`→sidecar IP, `--dns 192.0.2.1` (unreachable resolver) | **Airtight by construction** — the guest can reach nothing but the sidecar IP on its private network; DNS fail-closed; boot self-test proves severance; CI-gated | **Compatibility fallback only** — maintained, not developed, slated for removal once Apple Container is the sole target (issue #54). Also puts secrets on `docker run` argv (M1, accepted). |
| **Apple Container (host-only)** | augur-proxy runs **on the host**, bound to the **host-only gateway IP** (not `0.0.0.0`), started *after* the container attaches | Apple `--internal` is **host-only** (internet severed, host reachable); `--cap-drop NET_ADMIN`, `--no-dns` (empty resolv.conf), `HTTP(S)_PROXY`→gateway IP | Sudo-free equivalent of the sidecar for the primary engine; `--no-dns` confirmed live on macOS 26 (c28a3b1); gateway-bind keeps the proxy off the LAN (62a35a9) | **Host-only lets the guest reach other host services bound to `0.0.0.0`** — strictly weaker than Docker's isolated sidecar network. | **macOS VM (gvproxy)** | augur-proxy runs on **`127.0.0.1`** (SOCKS5); the VM's only NIC is a host-owned `AF_UNIX`/`SOCK_DGRAM` socket into **gvproxy** (forked gvisor-tap-vsock), which forwards all guest TCP to the proxy's SOCKS port by dest IP | User-space netstack: guest has no host-routable IP; `--deny-direct` drops UDP/ICMP *and* the guest-facing forwarder-management HTTP mux (port 80) — closing an API surface, not just the two protocols; `--dns-allowlist` gates DNS (A/AAAA/CNAME only — TXT/MX/NS/SRV refused, closing a covert-channel gap); only the ad-hoc-signable `com.apple.security.virtualization` entitlement (no `com.apple.vm.networking`) | Fully sudo-free VM egress with no privileged bridged-networking entitlement; SOCKS-filtered TCP is the sole egress; hermetic SSH (`-F /dev/null`) blocks host-env leak; `--dns-allowlist` is now a byte-parity Go port of the Swift `Allowlist`/`Hostname` matcher, unit-tested including the NUL-truncation case | **No in-guest boot self-test** (`verify_egress_locked` is Docker/Apple only); relies on `--deny-direct`/`--dns-allowlist` + SSH liveness. Depends on an **external forked gvproxy process**. Validated only manually on Apple Silicon (structural/entitlement checks are CI-covered; live NIC-count/UDP-ICMP-drop checks are not — see §5). |

### 2.1 New: base-image custom provisioning (PR #78)

An operator can pre-install extra packages into augur's *shared* base images at build time, before any project or workspace exists: a Homebrew package list for the macOS base VM (`~/.augur/provision/manifest.conf` + optional `hook.sh`/`hook.allowlist.conf`) or an apt package list for the Apple Container image (`~/.augur/provision/container-packages.conf`), driven from `augur:98-121,2422-3033`.

**Why a separate proxy identity.** On macOS this runs once, as root, inside the base-VM build/update (`run_base_provisioning`, `augur:2910-2960`), routed over a **dedicated** egress-filtered proxy/gvproxy pair (`start_provision_proxy`/`start_provision_gvproxy`, `augur:2699-2765`) rather than the per-project one — no project/workspace exists yet at base-VM build time, and `workspace_slug()` (which keys every per-project proxy/allowlist/socket file) has nothing to key off of. The dedicated identity uses fixed ports placed just past the per-project offset range (`augur:114-120`): `AUGUR_PROXY_HTTP_PORT_PROVISION=13999`, `AUGUR_PROXY_SOCKS_PORT_PROVISION=14999`, `AUGUR_SSH_FWD_PORT_PROVISION=20999` (per-project offsets top out at 13899/14899/20899, so collision is structurally impossible). File-naming reuses `$AUGUR_PROXY_DIR` with a leading underscore (`_macos-build-provision.*`, `augur:2670-2681`) — deliberate, since `workspace_slug()` maps every non-alnum byte including `_` to `-`, so a project slug can never sanitize to a leading-underscore name; the provisioning namespace is structurally disjoint from any real project's.

On **Apple Container**, the image build already runs with zero egress filtering (pre-existing, unchanged design), so `container-packages.conf` is only validated + TOFU-gated and its packages passed as a `--build-arg` (`container_provision_build_args`, `augur:3026-3033`) into `Dockerfile:23-28`'s `ARG EXTRA_APT_PACKAGES` / `apt-get install -y --no-install-recommends $EXTRA_APT_PACKAGES` — no new proxy needed there.

**Fixed baseline domains.** `provision_baseline_domains()` (`augur:2612-2620`) emits exactly: `formulae.brew.sh`, `ghcr.io`, `*.ghcr.io`, `github.com`, `*.githubusercontent.com`. Hardcoded, not user-editable, and deliberately mirrors (same domains/forms as) augur.conf's own Homebrew/GitHub sections rather than independently hand-picking a list — same apex/wildcard forms, no drift risk relative to what's already reviewed for the identical brew-fetch dependency. `hook.allowlist.conf` is the one escape hatch for package-specific extra domains (e.g. a cask's vendor CDN), merged in by `write_provision_allowlist` (`augur:2655-2668`) after passing `conf_line_valid` — same sanitization contract as the per-project allowlist.

**TOFU mechanism.** `files_content_hash` (`augur:2437-2443`) and `tofu_decide` (`augur:2457-2492`) are new *shared* primitives generalizing `check_project_conf_approved`'s existing TOFU pattern past one hardcoded file — parameterized on hash-cache-file, current hash, label, and a display callback. Both mechanisms remain independently correct: `check_project_conf_approved` still gates the per-project allowlist exactly as before (untouched by this PR), while `check_provision_approved`/`check_container_provision_approved` (`augur:2594-2598`, `3000-3004`) apply the same fail-closed-on-no-sha256, cache-compare, `AUGUR_ACCEPT_PROVISION_HOOK=1`/interactive-approval logic to the new files, with approvals cached at `~/.augur/provision-hashes/macos.sha256` — a separate cache from the per-project `~/.augur/project-hashes/` used by I7, so the two gates cannot cross-contaminate each other's approval state.

**Invariant inheritance.** Because this is a real augur-proxy/gvproxy instance built the same way as the per-project one, I1 (fail-closed), I2 (label-anchored matching), I3 (LDH validation), I4 (IP-literal deny), I5 (DNS fails closed via the same `--dns-allowlist`), I6 (hot-reload never falls open), and I8 (private-IP dial guard) are inherited by construction — same binaries, same code paths, just a different allowlist file and port set. I9 (macOS single-NIC VZ isolation) also holds unchanged: `run_base_provisioning` reuses the exact same `--net-vfkit=<sock>` VZ attachment mechanism (`augur:2928`), not a second NIC or bridged mode. I7's guest-cannot-widen-its-own-allowlist guarantee has no literal guest/project here, but its analog holds: the merged allowlist is written host-side (outside any guest-writable tree) and `hook.allowlist.conf` lines are sanitized via `conf_line_valid` before merge.

**New residual risk (not just "same risk, new place")** — see §6 item 12: `hook.sh` is TOFU-gated but is *executable content* (an arbitrary root script, `run_provision_hook` at `augur:2872-2878`, run via `sudo bash ...`), unlike every prior TOFU gate which only ever widens a *data* file (a domain list). This is qualitatively heavier and is called out explicitly rather than folded into the existing "TOFU gate" description.

## 3. augur-proxy filter internals

Dependency-free, cross-platform SwiftPM package — POSIX sockets only, no third-party deps. Two listeners over one shared allowlist: an HTTP CONNECT/forward-proxy (Docker datapath) and a SOCKS5 server (macOS/gvproxy datapath).

Re-verified line-by-line this snapshot against current source (no logic changes found versus 2026-07-02; only doc-comment path renames):

- **Fail-closed startup** (`main.swift:98-103`): dies if `--allowlist` is empty, dies if neither `--http-port`/`--socks-port` is set, dies (`exit(2)`) if `Allowlist.fromFile` returns nil (unreadable) — it refuses to start without a readable policy. Flags (`main.swift:50-57`): `--allowlist`, `--listen` (default `127.0.0.1`), `--http-port`, `--socks-port`, `--log`, `--pidfile`, `--allow-private` (sets `publicOnly=false`), plus `--max-connections`/`AUGUR_PROXY_MAX_CONNECTIONS` (`main.swift:33-41`, default 128, **still undocumented in the README**).
- **Allowlist matching (boundary-anchored)** (`Allowlist.swift:29-37,59-74`): `*.x`→subdomains only, `.x`→apex + subdomains, bare `x`→apex only. `allows()` lowercases, strips port + one trailing dot, rejects IP literals (line 64) and any host failing `isValidHostname` (line 68), then checks exact membership else `isSubdomain`. `isSubdomain` (lines 82-88) requires a `.` at the label boundary — so `*.github.com` matches `api.github.com` but **not** `evilgithub.com` or `github.com.evil.com` (tested).
- **Hostname validation (NUL-truncation guard)** (`Hostname.swift:11-33`): strict LDH on UTF-8 bytes, ≤253 total, per-label 1–63, rejects empty labels and NUL/space/underscore. Prevents `evil.com\0.github.com` matching the list yet dialing `evil.com`. Mirrored by the shell's `conf_line_valid` grammar.
- **HTTP CONNECT vs SOCKS5** (`ProxyServer.swift:71-105,109-170,176-195`): HTTP parses `CONNECT host:port` or absolute-form and dials upstream **by name**. SOCKS5 (no-auth, CONNECT only) receives IP-literal requests from gvproxy, so it peeks SNI/Host (`TLSClientHello.serverName`/`HTTPProxyRequest.hostFromOriginForm`), re-decides via `filter.decide`, then re-dials **by the peeked name** (never the original IP) — a spoofed SNI can't exfil elsewhere.
- **DNS pin table (scaffold — still unwired)** (`Filter.swift:39-56`, `PinTable.swift:9-13`): a thread-safe per-client `IP → {domain,expiry}` table that would re-allow an IP literal mapped to a still-allowed name. Fully implemented and unit-tested but **no production caller ever invokes `pin()`** (grep clean), so at runtime every IP-literal connect is denied unconditionally — the intended fail-secure state.
- **Hot reload (never falls open)** (`main.swift:139-168`): a background thread polls the allowlist mtime every 2s; a successful parse (even empty = deny-all) is applied atomically under lock (`Filter.swift:26-31`); an unreadable file keeps the previous policy. Reload never widens mid-request.
- **Dial-time SSRF guard** (`SocketIO.swift:65-91,201-218`, `AddressPolicy`): under `publicOnly` (production default, `main.swift:29`), `Sock.connect` skips any resolved address classified non-public (loopback, RFC1918, CGNAT, link-local, ULA, multicast, IPv4-mapped v6, NAT64, metadata `169.254.169.254`); unknown family refused. Applied to the same `getaddrinfo` result used to connect. `--allow-private` is never passed on any production path (grep clean, including the new provisioning code path).
- **Deny logging** (`Logger.swift:31-33`): one greppable `DENY client=… dst=host:port reason=…` line per block (`not-in-allowlist`, `ip-literal`, `no-sni`, `upstream-unreachable`) to file + stderr; ALLOW lines are stderr-only.

**Test results this snapshot**: `swift test` — **38/38 passed, 0 failures** (`AddressPolicyTests`, `AllowlistTests`, `ProxyRequestsTests`, `SNIAndFilterTests`, `SecurityTests`). No test files added/changed/removed since 2026-07-02; diff against that snapshot's commit touches only `README.md`, `Allowlist.swift`, `Logger.swift` doc comments (`.augur.conf`→`.augur/allowlist.conf` path strings), zero logic change. The new base-image provisioning feature does not touch `augur-proxy/Sources` or `Tests` at all — it drives a separate, dedicated proxy/gvproxy pair (macOS) built from the same unchanged binary, and no proxy at all for the Apple Container apt path.

## 4. Three-layer allowlist config model + TOFU

**Three layers, union-only merge** — each layer can *widen*, none can remove a lower layer's entries:

1. **Managed baseline** `~/.augur/augur.conf.default` — copied verbatim from repo `augur.conf` on **every install**.
2. **User global** `~/.augur/augur.conf` — scaffolded once, **never clobbered**.
3. **Per-project** `./.augur/allowlist.conf` — merged **sanitized only** (via `project_conf_domains` / `conf_line_valid`).

**Path change since 2026-07-02**: the per-project egress config moved from `./.augur.conf` to `./.augur/allowlist.conf` (`cebfba5`, `ede5f40`, 2026-07-04; "no backward-compat shim" — old-path configs are not auto-migrated). A sibling `./.augur/resources.conf` was added in the same change for CPU/memory sizing — it is **not** an egress control and carries no TOFU gate by design. `augur:56` (`AUGUR_PROJECT_CONF=$AUGUR_PROJECT_DIR/allowlist.conf`) and `INVARIANTS.md` I7 both already reflect the new path.

`write_merged_allowlist` cats baseline + global **verbatim**, then appends only sanitized project domains, and writes to `~/.augur/proxy/<slug>.allowlist` **outside the project mount** (`augur:659-674`) — so a root-in-guest editing the mounted `./.augur/allowlist.conf` **cannot widen its own policy mid-session** (invariant I7).

**TOFU approval** (`check_project_conf_approved`, `augur:838-901`): the project conf is fingerprinted (`sha256sum`/`shasum`; **fails closed if no hash tool**). New/changed → print the sanitized widening domains and prompt `[y/N]`; declined or non-interactive without `AUGUR_ACCEPT_PROJECT_CONF=1` → **exit 1 (fail closed)**. Approvals are stored host-side at `~/.augur/project-hashes/<slug>-<12-hex sha256 of full workspace path>`, keyed on the **full path** so a hostile same-basename repo can't inherit another project's approval, and never mounted so the guest can't forge it.

**Grammar** (honored identically by shell `conf_line_valid` and Swift `Allowlist`): `example.com` = apex only, `*.example.com` = subdomains only, `.example.com` = apex + subdomains.

**Current default baseline set — unchanged, still 18 patterns** (`augur.conf`, re-verified by direct read this snapshot):
- **Claude Code runtime**: `api.anthropic.com`, `.claude.ai`, `.claude.com`, `*.anthropic.com`, `statsig.anthropic.com`, `statsig.com`, `*.statsig.com`, `sentry.io`, `*.sentry.io`
- **GitHub**: `github.com`, `api.github.com`, `codeload.github.com`, `objects.githubusercontent.com`, `raw.githubusercontent.com`, `*.githubusercontent.com`
- **Homebrew/ghcr (macOS VM mode)**: `formulae.brew.sh`, `ghcr.io`, `*.ghcr.io`

`registry.npmjs.org` was dropped (PR #57 — the Swift image ships no node/npm); `.claude.ai`/`.claude.com` were broadened from apex-only. The baseline block is tagged `AUGUR_AGENT_SEAM` as the swappable per-agent surface, but there is **deliberately no agent-selection mechanism yet** — Claude Code is the only agent; per-agent baselines are design-only.

The new provisioning feature (§2.1) does **not** touch or extend this three-layer model — it has its own, entirely separate baseline (`provision_baseline_domains()`) and its own TOFU cache, deliberately kept disjoint from a live project's allowlist.

## 6. Known limitations & residual exfil channels

The threat model is *"contain a prompt-injected agent away from its host,"* **not** *prevent exfil through a legitimately allowlisted, credentialed host*.

1. **Allowlisted + credentialed host is an in-policy exfil surface.** `github.com` is allowlisted and a full-scope `GH_TOKEN` is injected → an injected agent can push data to an attacker-controlled repo entirely within policy. augur does not attempt to stop this.
2. **Wildcard / QNAME tunneling.** A broad wildcard (e.g. `*.githubusercontent.com`) permits `<data>.<wildcard>` leakage; mitigation is **allowlist policy, not the matcher**.
3. **Apple Container `0.0.0.0` host-reach (the accepted trade-off).** Host-only `--internal` lets the guest reach other host services bound to `0.0.0.0` — weaker than Docker's isolated sidecar network. A direct consequence of the **no-sudo constraint** (closing it needs host `pf` = sudo, which augur refuses), so it is documented, not enforced. Given the hard no-sudo rule, this is effectively **permanent**. (Distinct from the *inbound* LAN exposure already fixed by the gateway-bind commit 62a35a9.)
4. **No-sudo consequences ripple through the datapath.** "Never require sudo" took priority over stronger isolation, ruling out macOS `pf` and forcing host-only + host-side proxy (Apple) and `VZFileHandle` + gvproxy SOCKS (VM). The base-image provisioning feature extends this same principle rather than relaxing it: even its root `hook.sh` execution stays sudo-free from augur's own tooling perspective (it grants passwordless sudo *inside* the VM it owns, not on the host).
5. **TOFU auto-accept widens non-interactively.** `AUGUR_ACCEPT_PROJECT_CONF=1` widens egress without operator review (used by CI). The equivalent `AUGUR_ACCEPT_PROVISION_HOOK=1` now exists for the new provisioning gates (§2.1) and carries the identical risk shape.
6. **Credentials on Docker argv (M1).** Accepted Low under the single-user premise; **resurfaces on a shared host**.
7. **Basename-only slug collisions (~1/900).** Approval-hash and history dirs are full-path-keyed, but container/VM names and egress ports/subnet remain basename-keyed, so two same-basename projects running concurrently still collide on ports and subnet; recovery is a manual `AUGUR_INTERNAL_SUBNET`/`AUGUR_SIDECAR_IP` override. (VM *identity* collisions, a related but distinct risk, were separately closed by `90cb02f`'s machineIdentifier/macAddress regeneration on clone.)
8. **Every "accepted" residual assumes a single-user host.** On a shared host / CI runner, the argv secret exposure, name collisions, and cross-tenant reach all resurface.
9. **Fail-closed edges are hard errors, not graceful.** Proxy readiness is a fixed ~2s poll and gateway-iface readiness waits ≤5s; on slow bring-up the bind can still fail and `exit 1` (fails closed, but hard).
10. **Compatibility limits (fail-closed).** Connections with no recoverable SNI/Host (ECH/ESNI, non-TLS/non-HTTP) are denied; IPv6/IP-literal connects fail closed. augur's egress needs are all HTTPS, so this is accepted.
11. **Remaining stale docs.** The top-level `README.md`/install docs still mention `npm` in the baseline description though `registry.npmjs.org` was dropped. (The `augur-proxy/README.md` `host.docker.internal` line was fixed in PR #66.)
12. **NEW — base-image provisioning's `hook.sh` is TOFU-gated executable content, not a data file (qualitatively new trust decision).** Every prior TOFU gate in augur (project allowlist, and now the provisioning manifests themselves) only ever widens a *domain list* — worst case is added reachability. `hook.sh` (`run_provision_hook`, `augur:2872-2878`) is an arbitrary script that runs as root (`sudo bash ...`) once approved, after `run_base_provisioning` grants passwordless sudo (`augur:2943-2947`). Its network calls are still confined to the dedicated provisioning allowlist, but it has full local root on the base VM — which is later **cloned into every project's per-project VM**. A single mistaken approval poisons every subsequent clone until the next `augur update --macos`/rebuild. Mitigated only by TOFU review-before-approve and by the sudo grant being scoped/revoked on abort (`provision_fail`, `augur:2892-2901`); the underlying trust decision is heavier than approving a domain-pattern line and should be weighed accordingly by anyone approving a `hook.sh` diff.
13. **NEW — provisioning follow-up fix (`b8969fb`) is unmerged.** Not a security gap by itself (it fixes an SSH-PATH reliability issue, not an isolation control), but it means the shipped provisioning feature lacks a real-hardware-confirmed fix its own author already wrote. Worth closing before the feature sees wider use.

### Summary
Egress control is a **host-side, fail-closed, sudo-free domain-allowlist scheme shared by all 3 engines**, on by default, with a union-only three-layer merge, TOFU approval, and a Swift filter core (boundary matching, NUL defense, SNI re-decision, unconditional IP-literal deny, SSRF guard, non-fail-open hot reload) — all **unchanged and re-verified green (38/38 Swift tests, structural macOS-VM checks 11/11)** since 2026-07-02. The headline change this snapshot is **base-image custom provisioning** (PR #78): a Homebrew manifest for the macOS base VM and an apt manifest for the Apple Container image, both TOFU-gated, the macOS path routed over its own dedicated fixed-port egress-filtered proxy/gvproxy pair rather than any project's. It inherits every existing invariant by construction and adds one genuinely new risk shape — a TOFU-gated *executable* root hook rather than a data file, whose blast radius is every VM cloned from that base image. Also corrected this snapshot: the per-project config path move to `./.augur/allowlist.conf`, and the `ollama-llm-endpoint` branch's status from "active in-flight" to "closed/abandoned." The remaining intentional residual surfaces carried forward unchanged are the **Apple host-only `0.0.0.0` reach** (permanent under no-sudo), **in-policy exfil via an allowlisted credentialed host**, and the **macOS-engine containment lacking any CI gate** (validated manually on Apple Silicon only) — plus two open follow-ups to close: re-merging `b8969fb`'s provisioning SSH fix, and giving `hook.sh` approval the review weight it now warrants.
