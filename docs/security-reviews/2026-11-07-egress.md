## What the code now does for I10 (at `2978c2f`)

**One resolver for both modes: `resolve_session_credentials`** (`augur:484-542`, definition at `:520`).
- Resolves each `agent_auth_specs` credential (host env var, else its host file via `resolve_api_key`,
  `:454-461`) and `gh auth token` **once**, validates every value with `validate_secret_value`
  (`:471`; no single quote, no control byte) and also checks `agent_fixed_env`. Results go into the
  caller's `local _creds=()` (bash dynamic scoping). Every injection site writes those same values, so
  what is validated is what is injected; nothing re-reads a file between check and write.
- An **absent** credential is not an error. A credential file that **exists but cannot be read** is
  (`:525-528`): it returns 1 with an error naming the file, and every caller aborts with `|| exit 1`.
  Previously such a read yielded empty and the guest's working credentials would be replaced by none.
- Replaces `validate_resolved_credentials` and the second, separate resolution that each injection site
  did on its own.

**Container mode — property unchanged.** `cmd_claude` / `cmd_shell` call the resolver before
`ensure_session_container` (`:2971`, `:3002`) and pass `--env-file <(session_credential_env)` to
`eng exec` (`:2989`, `:3012`). `session_credential_env` (`:2856-2860`) now only prints the resolved
`_creds` with the builtin `printf`; no value is on any argv, `container run` still gets none, and
`_add_session_exec_env` adds the git helper off `creds_have_gh_token` (`:545`) rather than a second
`gh auth token`.

**macOS mode: `push_macos_guest_env`** (`augur:4037-4110`, definition at `:4057`).
- **Stdin only.** The whole `~/.augur-env` content, including `export VAR='<value>'` lines for each
  `_creds` entry, is built host-side and piped in by the builtin `printf` (`:4098`). The remote command
  string `_cmd` (`:4091-4094`) holds no value: only paths, the end marker, the `~/.zshenv` source line
  (`:132`) and the git helper, which references `$GH_TOKEN` and is expanded guest-side
  (`macos_git_credential_helper_cmd`, `:4027-4031`).
- **Atomic, never world-readable.** The guest writes to `~/.augur-env.tmp.$$` inside
  `( umask 077 && cat > … )`, so the file is mode 600 before the first secret byte. It is renamed over
  `~/.augur-env` only if its last line is `MACOS_AUGUR_ENV_END_LINE` (`:4035`); otherwise the temp file
  is removed and the guest exits 1 with the old file in place (`:4092`).
- **Age-based temp cleanup.** Each push first removes `~/.augur-env.tmp.*` older than a minute
  (`find … -mmin +1`, `:4091`), i.e. leftovers of a push killed mid-write that may hold revoked
  secrets, while a concurrent push's fresh temp file survives. `macos_scrub_augur_credentials`
  (`:4756-4761`) removes all of them unconditionally.
- **One ssh per push.** The env file, the `~/.zshenv` line (exit 4 on failure) and the git helper
  (exit 3, warn only) go in one `ssh_macos` session. Outcomes: 0 ok; 3 warn and succeed; 1 "unchanged";
  4 "installed but not sourced"; anything else (ssh's 255) "unknown outcome" (`:4099-4109`).
- **Callers.**
  - `cmd_up_macos` boot path (`:4325-4543`): resolves at `:4397`, before the clone, `augur-vm set` and
    `run`; boot self-test at `:4498`; `~/.gitconfig` scp at `:4528-4529`; push at `:4536`, fatal.
  - `cmd_up_macos` running branch (`:4342-4385`): admin-password check (`:4345`), egress-mode check
    (`:4348`), allowlist rewrite and proxy revival, clock and timezone, then **self-test (`:4378`) →
    resolve (`:4383`) → push (`:4384`, fatal)**. Credentials therefore reach only a guest just proven
    contained, and a bad credential cannot cancel the reconcile or the self-test.
  - `prepare_macos_session` (`:4554-4585`), called by `cmd_claude_macos` (`:4592`) and
    `cmd_shell_macos` (`:4606`): a stopped VM goes through `cmd_up_macos` (`:4556-4559`). A running VM
    gets the egress-mode check (`:4563`), resolve (`:4566`) before any guest step, clock and timezone
    (`:4571-4572`), then the push (`:4578`), whose failure only warns, so the session opens on the
    guest's existing `~/.augur-env`.
  - `setup-token` (both modes) does not call the resolver or the push, as before.

**Accepted trade-offs, as commented in code.**
- **No fresh self-test before a `claude`/`shell --macos` push to a running VM** (`:4574-4577`). Same
  as Container's per-session `exec`: credentials go to a guest whose containment was proven at its last
  `up`. The reuse-path spoofing caveat (item 46's project-VM half in 2026-11-05) applies unchanged.
- **Concurrent-command gaps** (`:4550-4553`). augur does not support two commands on one project at
  once: a session can push to a VM whose concurrent `up` has not finished its self-test, and a VM that
  comes up between the running check and `cmd_up_macos` takes the already-running branch, which skips
  the `ensure_*` wiring.
- **Duplicate `~/.zshenv` line** (`:4083-4085`). Two racing pushes can both append the source line;
  it only sources the same file twice, and the scrub removes every copy.

## Contract vs code

No divergence on the argv property. One wording nuance, no mark impact: the Rule says the credentials
are written "by every" `up`/`claude`/`shell --macos`. That is attempted on every one, but on
`claude`/`shell` against a running VM a failed push only warns and the session opens on the guest's
previous `~/.augur-env` (`:4578-4579`); `up` exits 1. This is a freshness guarantee, not an argv one,
so I10's property holds either way.
