## 1. Essence

augur egress control is a **host-side, fail-closed, on-by-default domain allowlist** that confines a
possibly prompt-injected coding agent (Claude Code today), running on a trusted single-user host, by
forcing *all* guest outbound traffic through **augur-proxy** — a dependency-free Swift forward proxy
that runs as the ordinary host user **with no sudo**. The guest is severed from direct egress and its
only route out is the proxy, which re-resolves each connection **by hostname** and admits it only if
it matches a **union-only, three-layer domain allowlist** (managed baseline + user-global +
per-project); everything else is denied and logged. Egress is on by default (`AUGUR_EGRESS=auto`,
`augur:88`), unrecognized values fail *on* (`egress_enabled`, `augur:672-677`), and the same
allowlist/enforcement contract is shared across both engines — literally so on the DNS side, where
gvproxy's matcher is a declared byte-parity Go port of the proxy's Swift one
(`gvproxy/augur-egress.patch:166-169`). The design principle is **containment,
not exfiltration-proofing** — a formally closed decision
([ADR-0008](../decisions/0008-exfiltration-ceiling-accepted.md)).

The shape is unchanged since 2026-07-23. What moved this cycle is **the second engine catching up
with the first, and the host-state namespace becoming per-project**. Three properties that the
contract already claimed were not actually true of the shipped code, and are now: I1's boot tripwire
exists on **both** engines rather than only on Apple Container (#131); it runs on **every** `up`
including the already-running short-circuit rather than only on fresh-create and stopped-reuse
(#128); and I7's "written host-side, outside the project tree" is now enforced by a guard rather than
assumed, because a workspace that *contained* `~/.augur` used to put the enforcement file inside the
read-write share (#126). One invariant's rule text moved to match reality (I7, #127): every
per-project egress host-state file is now keyed on the **full** workspace path, closing a case where
two same-basename projects shared one live policy file. Four smaller fixes harden the macOS lifecycle
(credentials validated before the clone, the git helper, `down` verifying the stop, the gvproxy
socket unlink order) and one adds a new capability with new residuals (the guest clock, #133).

**Nothing in this series exercised a real guest.** That is the honest frame for everything below —
see §5 PARTIAL.

## 2. Enforcement boundary per engine (still two engines)

Both engines share the *same* merged allowlist and the *same* augur-proxy filter core; they differ
only in **where the proxy runs** and **how the guest is severed from direct egress**. Every element
below was re-verified against current code this snapshot. The enforcement *elements* are unchanged
from 2026-07-23 in container mode; what changed on the macOS side is that a **boot tripwire now
exists at all**.

### 2.3 Container lifecycle: persist-and-reconcile (reshaped this snapshot, #128)

The persist-and-reconcile shape from #114 is unchanged; what changed is what happens when the
container is **already running**, which was previously a no-op:

- **`down` STOPS and keeps** the container + egress network (`cmd_down`, `augur:2293-2321`) —
  unchanged.
- **`up` on a stopped container** re-ensures the network and `eng start`s it, then `finish_up`
  (`augur:1996`) — unchanged.
- **`up` on a RUNNING container now reconciles** (`augur:1954-1979`) instead of returning 0. See
  "What changed". The refusal on fingerprint drift (`augur:1972-1976`) is new and is a hard `exit 1`.
- **One-time upgrade effect, deliberate:** `container_fingerprint` (`augur:1681-1721`) hashes
  `subnet` + `gw` + `http-port`, all three of which move with #127's new offset, so the digest flips
  and every existing container is recreated once on the next `up`. That is what makes the new wiring
  real rather than silently wrong: a container created before the re-keying has the **old** proxy URL
  baked into `HTTP_PROXY` at `container run` time and cannot pick up the new one. Only the throwaway
  writable layer is lost. *Caveat found this review and not exercised:* the fingerprint does **not**
  cover `egress_network_name()`, and both the subnet (`augur:77`) and the HTTP port (`augur:80`) have
  `${VAR:-}` override forms — so an operator who pins both would get an unchanged fingerprint and no
  recreate while `ensure_egress_network` creates the new hash-named network. INFERRED; it may well
  fail loudly on the duplicate subnet rather than diverging silently, but it was not tested (no
  container engine in this environment).

### 2.4 macOS lifecycle: the reconcile path and what a live VM cannot absorb (new this snapshot)

`cmd_up_macos`'s already-running branch (`augur:3275-3304`) runs, in order: `warn`; if
`egress_enabled` → `check_project_conf_approved` (`augur:3278`) and `start_proxy "127.0.0.1"`
(`augur:3283`, which also revives a proxy that died under a live VM — the only recovery, since
gvproxy dials `--socks-upstream` per **connection**); `warn_if_macos_egress_pinned` (`augur:3286`);
`sync_macos_guest_clock` (`augur:3293`); `verify_macos_egress_locked` (`augur:3302`); `return 0`.

It never `exit 1`s on drift because there is no `container_fingerprint` on this engine
(`augur:3270-3274`). Instead it **warns** about the three things a live VM genuinely cannot absorb:
the DNS allowlist gvproxy snapshotted at boot, VM sizing (`augur-vm set` requires the VM stopped),
and `~/.augur-env` credentials. The warning needs no new state file — it fires on
`[[ "$allowlist" -nt "$gvp_pid" ]]` (`augur:3011-3026`), because the gvproxy pidfile is written at
the instant gvproxy snapshotted the allowlist. **That comparison is only exact because of #128's
content-idempotent write** (an unconditional header rewrite would make it cry wolf on every `up`) and
only project-safe because both names are path-hash-keyed by #127. It is silent when either file is
absent — including under `--no-egress`, which matters for §6 item 24.

Asymmetry worth stating plainly, because INVARIANTS.md's new I1 text does not carry it: on the
**fresh** path the self-test runs only when egress is ON (`augur:3441`, under a comment restating
the rule at `augur:3438-3440`); on the **reconcile** path it runs **unconditionally** (`augur:3302`
— the `if egress_enabled` block that opened at `augur:3277` has already closed at `augur:3284`).
That is not a design asymmetry anyone chose: the header of `verify_macos_egress_locked` itself says
"`--no-egress` skips the whole self-test, as it does in container mode" (`augur:1511`), and
container mode does (`finish_up`, `augur:1917-1920`). The reconcile call site contradicts the
function it calls; §6 item 24 records what that costs an operator today.

### 2.5 Workspace containment: what `require_safe_workspace` does and does not cover (new this snapshot)

Covered in "What changed" and ADR-0014. Three properties to keep in front of a future reader:
(a) it is gated to `up|claude|shell|setup-token` only (`augur:4951`), by design;
(b) it does **not** re-base `WORKSPACE_DIR` — the physical paths are computed locally inside the
function on purpose (`augur:976-982`), because `workspace_path_hash` feeds container names, VM names,
the TOFU approval key and every per-project state dir, so re-basing on `pwd -P` would silently rename
all per-project state for anyone whose path crosses a symlink;
(c) there is deliberately **no** escape hatch — no `AUGUR_ALLOW_HOME_WORKSPACE` — and relocating
`AUGUR_DIR` is not a workaround, since it is an unconditional assignment (`augur:41`) and `~/.augur`
stays on PATH via the shell rc regardless. Verified by mutation this review: deleting the single
`augur:4951` call site turns `tests/11_construct_container.sh` red on 27 assertions (R1 root, R2
`$HOME`, R3 ancestor of `$HOME`, R4 `$AUGUR_DIR`, R4 inside `$AUGUR_DIR`, symlinked cwd) and
`tests/30_macos_vm.sh` red on 4 (the cross-mode proof that the guard precedes `require_vz`).

## 6. Known limitations & residual exfil channels

The threat model is *"contain a prompt-injected agent away from its host,"* **not** *prevent exfil
through a legitimately allowlisted, credentialed host*. Items 1–6, 8–11, 13–23 carry forward from
2026-07-23; item 7 and half of item 12 **close**; twelve items are new or re-instated (24–35).

1. **Allowlisted + credentialed host is an in-policy exfil surface — a closed, permanent decision.**
   `github.com` allowlisted (`augur.conf:29-31`) + a full-scope `GH_TOKEN` injected (`augur:2154`) →
   an injected agent can push data to an attacker repo entirely within policy.
   [ADR-0008](../decisions/0008-exfiltration-ceiling-accepted.md) (issue #24, closed) declines to
   mitigate this by default or opt-in — not TLS MITM/DLP, not per-service authorization, not the
   lighter `--no-token`/read-only-mount middle ground. **Unchanged by this series.**
2. **Wildcard / QNAME tunneling.** A broad wildcard (`*.githubusercontent.com`, `augur.conf:34`)
   permits `<data>.<wildcard>` leakage; I2's label-boundary anchoring bounds the **match**, not the
   QNAME content. Mitigation is allowlist policy, not the matcher. **Unchanged.** One bound worth
   carrying forward: on the macOS engine gvproxy admits only `A`/`AAAA`/`CNAME` and refuses every
   other qtype (`gvproxy/augur-egress.patch:113-119`), so the high-bandwidth `TXT`/`NULL` **response**
   channel is closed and what remains is data in the QNAME **labels** of a name→address query to an
   allowlisted name; container mode has no in-guest resolver at all (`--no-dns`, `augur:2047`).
3. **Apple Container `0.0.0.0` host-reach (accepted trade-off).** Host-only `--internal`
   (`augur:2033`) lets the guest reach other host services bound to `0.0.0.0` (raw TCP, not
   proxy-mediated). A direct consequence of the no-sudo constraint; documented, not enforced,
   effectively **permanent** ([ADR-0001](../decisions/0001-sudo-free.md)). #127 renamed the network
   but did not change its routelessness — only the specific /28 moves, once, per project.
4. **No-sudo consequences ripple through the datapath.** Every fix in this series is a refusal, a
   verification or a host-side reorder rather than an escalation (ADR-0014:213-215). Worth adding:
   #133 uses **guest**-side `sudo -S` with the documented fixed ADR-0007 password (`augur:3225`),
   which keeps the *host* sudo-free — and NTP was rejected as the alternative precisely because UDP
   has no path out (`augur:3151-3157`).
5. **TOFU auto-accept widens non-interactively.** `AUGUR_ACCEPT_PROJECT_CONF=1` /
   `AUGUR_ACCEPT_PROVISION_HOOK=1` / `AUGUR_ACCEPT_CERT_INSTALL=1` all still present. Worth
   contrasting: #126's workspace guard deliberately has **no** comparable escape hatch.
6. **Credentials on Apple Container `container run -e` argv (M1) — and at rest in the kept
   container's config.** Unchanged (`augur:2065,2154`); `down` still keeps the container, `destroy`

   rather than silently persist, narrowing the staleness window but not the exposure. **Carried
   forward from 2026-07-23 item 6 as a checked-and-refuted answer, re-derived at this tip: the
   fingerprint file is not itself a second, recoverable at-rest secret.** `container_fingerprint`
   (`augur:1681-1723`) pipes the resolved secret *values* through `sha256sum`/`shasum -a 256` and
   emits only the resulting **digest** (`augur:1722`); `write_container_fingerprint`
   (`augur:1732-1735`) writes that digest under `umask 077` to
   `$AUGUR_DIR/container-state/<container-name>.fingerprint` (`container_fingerprint_file`,
   `augur:1668-1673`) — host-side, outside the project tree, exactly as the code claims at
   `augur:1680`. And `destroy` clears **both** copies: the container itself (`engine_rm_force`,
   `augur:2330`) and the digest (`augur:2336`). So "does augur persist a credential digest on

   **resurfaces on a shared host**.

### Summary

Egress control is unchanged in **shape** since 2026-07-23 — a **host-side, fail-closed, sudo-free
domain-allowlist scheme shared by two engines** (Apple Container + macOS VM), on by default, with a
union-only three-layer merge, TOFU approval, and a Swift filter core — all **re-verified green
(54/54 Swift, `tests/run.sh` ALL GREEN: 24 scripts, 731 assertions, 0 failed, 4 expected live-tier
skips)** on 2026-07-26. `augur-proxy/`, `augur-vm/`, `gvproxy/augur-egress.patch` and `augur.conf` are
**byte-identical** to the base, so §3 and the default-domain set carry forward mechanically. What
moved this cycle is that **three properties the contract already claimed became true of the shipped
code**: I1's boot tripwire now exists on *both* engines (#131) and runs on *every* `up` including the
already-running short-circuit (#128), and I7's "outside the project tree" is now enforced by a guard
(#126) rather than assumed. One rule text changed — I7 is now scoped to the project the approval was
granted for, keying every per-project egress host-state file on the full workspace path (#127), which
is what makes this snapshot a contract-change artifact rather than a keep-it-green cycle. Three
statements in the 2026-07-23 snapshot are corrected here by name, and two more (its "macOS has no
in-guest self-test" and its "single-NIC construction is machine-checked") are corrected in §5. The
"checked & refuted" class from 2026-06-28 is **re-instated after six snapshots of omission**, with
two entries retired for cause and one refutation (the history-leaf symlink) explicitly *not*
re-asserted because its premise no longer describes the code. Twelve residuals are new or
re-instated, of which the ones a reader should act on are the **unguarded `egress_enabled` on the
macOS reconcile self-test** (item 24 — a fail-closed teardown of a `--no-egress` VM, unacknowledged
by any commit message), the **unactionable remedy on `require_socket_path_fits`'s hard exit** (item
25), and the **complete absence of any test guarding the production argv on either engine** (item 32,
mutation-proven). The **RW-workspace `.git/hooks` host-code-execution path** (item 12) remains the
single highest-impact residual, explicitly preserved. And the honest frame for all of it: **none of
the nine PRs, and none of this review, exercised a real guest** — every macOS mechanism here is proven
by a bash stand-in for `ssh_macos` plus reasoning plus a handful of probes re-measured by hand, and
`tests/e2e_macos_vm.sh` remains the only live gate and is `AUGUR_TEST_LIVE`-gated.
