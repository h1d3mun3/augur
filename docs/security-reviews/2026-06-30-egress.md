> **Security-review snapshot — as of 2026-06-30 / focused on egress control.**
> This is a point-in-time record and is **not maintained** (once stale, the date makes that obvious).
> For the operating rules and the list of snapshots, see [`README.md`](./README.md). Regenerate with the `augur-egress-survey` workflow.

## 1. Essence (in one line)

augur sandboxes a coding agent (Claude Code) on a **trusted, single-user host** and confines its **outbound traffic to a domain allowlist**. The core is `augur-proxy` (a dependency-free Swift forward proxy) that **runs as the host user and never uses sudo**. It is the single egress decision point shared by all three execution engines.

The design principle is **"host-side, fail-closed, union-only allowlist":**
- The guest is placed on an `--internal` network with `NET_ADMIN` dropped and external DNS killed, so its **only way out is the host-side proxy**.
- The proxy **re-resolves the destination hostname by name** and only lets it through when it matches the allowlist by strict label-boundary matching.
- **On by default** (`AUGUR_EGRESS=auto`), **fail-closed on every engine** (refuse to start if the allowlist can't be read, deny on a parse failure, and if the boot self-test finds direct egress reachable, tear the container down immediately).
- The merged allowlist is written under `~/.augur/proxy/` (**outside the project tree**), so **the guest cannot widen its own policy mid-session**.

The stated threat model (`docs/security-reviews/2026-06-28-full-review.md:8-31`) is **"contain a possibly prompt-injected agent away from its host,"** **not** to prevent exfiltration through a legitimately-allowlisted, credentialed host (see below).

## 2. Enforcement boundary per engine

All three engines converge on the **same merged allowlist** and the **same `augur-proxy` filter**. They differ only in the datapath that funnels guest traffic to the proxy and in how airtight that funnel is.

| | **Docker (sidecar)** | **Apple Container (host-only)** | **macOS VM (gvproxy/SOCKS5)** |
|---|---|---|---|
| Proxy location | Linux `augur-proxy` as a **sidecar container** (dual-homed) | **Host-side** native proxy bound to the host-only gateway IP | **Host-side** native proxy on `127.0.0.1` |
| Path to the proxy | agent → sidecar fixed IP via HTTP CONNECT; the sidecar's other leg is a bridge (the only way out) | agent → host-only gateway IP (`HTTP(S)_PROXY`) | guest's only NIC = a host-owned socketpair → forked **gvproxy** user-space stack → all TCP to the proxy's **SOCKS5** |
| Network severance | `docker network --internal`: host and internet both severed | Apple `--internal` is **host-only** (internet severed but **host reachable**) | gvproxy is the entire guest stack; `--deny-direct` drops UDP/ICMP |
| DNS kill | resolver → unreachable TEST-NET `192.0.2.1` | `--no-dns` (no resolver at all; **confirmed on macOS 26**) | gvproxy gateway DNS: NXDOMAIN / rejects record types other than A/AAAA on the same allowlist |
| Anti-reroute | `--cap-drop NET_ADMIN` | `--cap-drop NET_ADMIN` | the host owns the stack |
| Boot self-test | `verify_egress_locked` (fail-closed) | `verify_egress_locked` (fail-closed) | **no in-guest leak probe** (relies on `--deny-direct` + `--dns-allowlist`) |

**Strengths and weaknesses per engine:**
- **Docker** — *airtight by construction.* But it is a **compatibility fallback** — no new features, slated for eventual removal (issue #54, `augur:159-162`).
- **Apple Container (recommended / primary)** — inbound is on par with Docker (proxy bound to the gateway IP, off the LAN; commit `62a35a9`). **The key accepted trade-off:** because it is host-only, the guest **can reach host services bound to `0.0.0.0`** (weaker than the Docker sidecar). Closing it would need pf rules = sudo, which augur avoids, so it is **documented only, not enforced** (`augur:804-806`). Apple Container can't dual-home, so the sidecar model isn't available, and because the gateway interface only comes up after the container attaches, the proxy is **started after the container attaches** (commit `0e84858`).
- **macOS VM** — *the tightest topology.* Uses no Apple-gated `com.apple.vm.networking` entitlement. **Weakness:** there is **no in-guest leak self-test** equivalent to `verify_egress_locked`. It depends on an external gvproxy fork (pinned `af3ea886` + `augur-egress.patch`, Apple-Silicon-only, not runnable on Linux/CI). A self-DoS where a runt frame panics gvproxy (A5) is also known (a guard is planned).

## 3. Inside the augur-proxy filter

Dependency-free SwiftPM (POSIX sockets only; builds offline on Linux+macOS). Two listeners (HTTP CONNECT / SOCKS5) → a single `Filter`.

- **Allowlist matching (the core):** `*.x` = subdomains only / `.x` = apex + sub / `x` = apex only. `isSubdomain` requires the character before the suffix to be a `.` → `*.github.com` matches `api.github.com` but **not `evilgithub.com`**, and not the apex `github.com` (`Allowlist.swift`).
- **LDH hostname validation** (`Hostname.swift`): strict LDH; rejects empty labels / whitespace / underscores / **NUL** → blocks the `evil.com\0.github.com`-style **getaddrinfo NUL-truncation bypass**.
- **The DNS pin table is "implemented but a dead scaffold at runtime":** `PinTable.swift` exists and is tested, but **there is no in-process DNS resolver/responder and nothing calls `pins.pin()`**. So **IP-literal connects are always denied** (fail-secure). This is noted in comments too. (The review earlier mislabeled this a "live DNS-pin defense." The live DNS gate is a **separate process on the gvproxy side** — don't conflate the two.)
- **SOCKS5 path:** because gvproxy forwards by IP, after connecting the proxy recovers the hostname via `peekHostname()` from the **TLS ClientHello SNI / HTTP Host**, then **re-decides by name and re-resolves by name for the upstream connection** (a spoofed SNI can't escape elsewhere). No hostname = `deny("no-sni")`.
- **SSRF / private-IP guard:** `Sock.connect` inspects the resolved address and blocks private/loopback/link-local/metadata, etc. augur **never passes `--allow-private`**, so this is always on.
- **Hot reload (never falls open):** mtime polling. If readable (even empty/garbage → deny all) it is applied atomically; **if unreadable, the previous policy is kept.**
- **Fail-closed startup + deny log:** unreadable allowlist → `die()`; empty → records "all egress denied." Denials are one greppable line each (`not-in-allowlist` / `ip-literal` / `no-sni` / `upstream-unreachable`).

## 4. Allowlist configuration model

**3-layer union-only merge** (a layer can widen but not narrow the ones below; `augur:42-50`):
1. **Managed baseline** `~/.augur/augur.conf.default` — **overwritten on every install** from the repo's `augur.conf`. Carries the `AUGUR_AGENT_SEAM` marker (for swapping the agent).
2. **Global** `~/.augur/augur.conf` — scaffolded once, **never clobbered** after.
3. **Project** `./.augur.conf` — **TOFU-gated**; only sanitized domains are merged.

`write_merged_allowlist()` writes `~/.augur/proxy/<slug>.allowlist` (**outside the mount**), so a guest editing `./.augur.conf` can't widen it.

**TOFU approval** (`augur:680-739`): fingerprint `./.augur.conf` with SHA-256. On new/changed, show the domains being widened and the count of invalid lines and prompt `[y/N]`. The approval hash is keyed on **slug + full-path hash** → two same-named directories don't share approval. `AUGUR_ACCEPT_PROJECT_CONF=1` auto-accepts; non-interactive without it → fail-closed.

**Current default domains** (`augur.conf`):
- Claude Code: `api.anthropic.com`, `.claude.ai`, `.claude.com`, `*.anthropic.com`, `statsig.anthropic.com`, `statsig.com`, `*.statsig.com`, `sentry.io`, `*.sentry.io`
- GitHub: `github.com`, `api.github.com`, `codeload.github.com`, `objects.githubusercontent.com`, `raw.githubusercontent.com`, `*.githubusercontent.com`
- Homebrew/ghcr: `formulae.brew.sh`, `ghcr.io`, `*.ghcr.io`
- **`registry.npmjs.org` was dropped** (commit `4be388d`, PR #57) — Claude Code installs via the official native installer (no npm), the `FROM swift` image ships no node/npm, and it was unused.

## 6. Known limits and residual exfil channels (the honest threat model)

- **Allowlisted + credentialed hosts are an in-policy exfil surface** (the top caveat): `github.com` is on the allowlist and the guest holds a full-scope `GH_TOKEN`, so an injected agent can push data to an attacker's repo **within policy**. augur does not claim to stop this.
- **Tunneling via a wildcard:** `<data>.<allowed-wildcard>` (e.g. `*.githubusercontent.com`). Mitigation is on the allowlist "policy" side.
- **The Apple `0.0.0.0` trade-off** (accepted, documented, unmitigated): being host-only, the guest can reach host `0.0.0.0` services. Closing it needs pf = sudo, so it is declined.
- **The consequence of avoiding sudo:** "never require sudo" takes priority over weaker isolation. This ruled out macOS pf and led to host-only + host-side proxy (Apple) and VZFileHandle + gvproxy SOCKS (VM). The `0.0.0.0` reach above is a direct consequence.
- **The DNS pin table is dead:** IP literals are denied unconditionally (fail-secure). ECH/ESNI and non-TLS/non-HTTP streams yield no hostname → `no-sni` deny (fail-closed, but also un-allowable by name).
- **Implicit widening via TOFU auto-accept:** `AUGUR_ACCEPT_PROJECT_CONF=1` widens egress non-interactively without operator review.
- **Per-project derivation collisions** (~1/900): port/subnet collisions need a manual override. Container/VM names and ports are basename-keyed, so two same-basename projects running at once still collide.
- **Premise-dependent:** every "accepted" residual assumes a single-user host. On a shared host or CI runner, argv secret exposure, name collisions, and cross-tenant reach resurface.
- **Stale doc:** `augur-proxy/README.md:18-22` says the Docker path goes via `host.docker.internal`, but the current script uses the dual-homed sidecar's fixed IP and `host.docker.internal` does not appear (needs fixing).

---

### Summary
Egress control is **implemented and merged** as a **host-side, fail-closed domain-allowlist scheme shared by all 3 engines**, with sudo-free operation, on-by-default, union-only merge, TOFU approval, and strict matching / NUL defense / SNI re-decision / SSRF guard all in place. The key current-state points are: **containment is verified on real hardware (macOS 26) only once, manually**, with no CI gate; **the Apple host-only `0.0.0.0` reach** and **in-policy exfil through an allowlisted credentialed host** are intentional residual surfaces; and **the only active unmerged work is the local-LLM (Ollama) support in `feature/ollama-llm-endpoint`**.
