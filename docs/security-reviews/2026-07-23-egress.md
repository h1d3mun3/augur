- **New — idle timeout on established tunnels (`f5af0fb`, #101), closing the one residual the
  2026-07-20 snapshot logged as open.** A new pure core `IdleTimeout.swift` adds a
  reference-typed `IdleTracker` — one clock per *bidirectional* tunnel, shared by both splice
  directions so a byte moving *either* way resets it (`IdleTimeout.swift:32-57`) — plus three
  pure classifiers (`classifyRead` `:71-76`, `classifyWrite` `:88-92`, `idlePollSecs` `:97-99`)
  that map `read()`/`write()`/errno results to teardown-vs-continue and are exhaustively
  unit-tested. `expired()` uses a `&-` wrapping subtract (`:52-55`) so a (never-occurring)
  backwards monotonic clock can't trap. Wiring: `ProxyServer.spliceBoth` builds an `IdleTracker`
  and sets `SO_RCVTIMEO`+`SO_SNDTIMEO` on **both** fds when idle > 0, else restores the exact
  pre-#101 infinite-idle path (`ProxyServer.swift:254-288`); `Sock.splice` gains an optional
  `idle` param and, on idle expiry, shuts down **both** fds jointly (avoiding a re-creation of
  the #36 slot-leak deadlock one layer down), whereas the normal EOF/error path keeps the
  original single half-close so an in-flight opposite direction is never truncated
  (`SocketIO.swift:206-249`). A new `Sock.setWriteTimeout` (`SocketIO.swift:147-150`) bounds the
  write side so a guest that *stops reading* can't pin a `connectionCap` slot via a blocked
  write. A documented **load-bearing invariant** (`SocketIO.swift:202-205`): both fds must stay
  BLOCKING so the only EAGAIN source is the `SO_*TIMEO`; making them non-blocking would hot-spin
  the `.idleTimeout` `continue`. **Confirmed this does NOT weaken allow/deny:** `spliceBoth` runs
  only *after* `filter.decide()==allow` and the upstream connect; the classifiers touch no
  allowlist / hostname / IP-literal / SSRF logic; with `idle==nil` the datapath is byte-for-byte
  pre-#101. On by default at **900 s** (`--idle-timeout` / `AUGUR_PROXY_IDLE_TIMEOUT`, flag > env
  > default, `main.swift:34-39,48-51,65,101-104,123-126`); `0` restores the old infinite-idle
  behaviour exactly. This is a posture strengthening (bounds the #101 slot-pin DoS by default)
  but is a genuine default-behaviour change from the 2026-07-20 state where no idle timeout
  existed. New live CI tier `tests/25_proxy_idle_timeout.sh` (real-binary: idle reclaim + slot
  release through a cap of 1, SSE-style preservation, `--idle-timeout 0` disable, and normal
  half-close not truncating the opposite direction). **Retires §6 item 19 / issue #101** from the
  prior snapshot's residual list. `I1–I10` unaffected — bounded-DoS hardening only.
- **Fixed — I7 TOCTOU: honor the APPROVED snapshot, not a post-approval live re-read
  (`f3c2d35`).** Before: `check_project_conf_approved` fingerprinted the guest-writable live
  `./.augur/allowlist.conf` at approval time, but `write_merged_allowlist` rebuilt the honored
  allowlist *later* at proxy start by **re-reading that same live mounted file**, with no hash
  re-verification between approval and use — a check/use split a guest could race. Most
  concretely across two engine modes on one repo: the approval key is `slug + path-hash`
  (mode-agnostic, `augur:818-821`), so mode B does not re-prompt, and an already-running mode-A
  guest could append a grammar-valid (`conf_line_valid`-passing) pattern during mode B's slow VM
  clone/boot — between B's approval-check (`augur:1330` container / `augur:2232` macOS,
  explicitly "before cloning or starting the proxy") and B's merge (`augur:941` via
  `start_proxy`). Adding `proxy_role` to the key would **not** fix it — the check/use split is
  the defect. After: `check_project_conf_approved` copies the live conf **once** to a host-side
  stable `mktemp` copy (`augur:853-856`), then derives the fingerprint (`:858`), the sanitized
  domain snapshot (`:872`) and the dropped-line count (`:873`) **all from that single copy**, and
  persists the snapshot to `~/.augur/project-hashes/<slug>-<pathhash>.domains`
  (guest-inaccessible; `write_project_snapshot` `augur:693-695`). `write_merged_allowlist` now
  reads `$snap=…​.domains` (`augur:607`) and emits the project block from the snapshot
  (`augur:619-625`), **never** a fresh read of the live mounted file; a missing snapshot **fails
  closed** by omitting the project block (a more restrictive allowlist, `augur:623`). Because
  `sha256(faithful copy) == sha256(original)`, existing recorded approvals still match — no
  re-prompt on upgrade — and the snapshot is (re)written on **every** approval path including the
  already-approved fast path (`augur:879-884`, healing pre-snapshot approvals). Tested: a domain
  appended *after* approval is not honored, and the tamper is detected on the next check and
  fails closed non-interactively (`augur:921-923`). **I7 strengthened; I1 fail-closed preserved.**
- **Follow-up hardening — emitter `return 0` guard + temp-copy leak closed (`e565551`),
  adversarial-review fixes both missed by CI because `tests/lib.sh` runs without `set -e`.**
  (1) `project_conf_domains` inherited its trailing while-loop exit status — `1` when the conf's

## 1. Essence

augur egress control is a **host-side, fail-closed, on-by-default domain allowlist** that
confines a possibly prompt-injected coding agent (Claude Code today), running on a trusted
single-user host, by forcing *all* guest outbound traffic through **augur-proxy** — a
dependency-free Swift forward proxy that runs as the ordinary host user **with no sudo**. The
guest is severed from direct egress and its only route out is the proxy, which re-resolves each
connection **by hostname** and admits it only if it matches a **union-only, three-layer domain
allowlist** (managed baseline + user-global + per-project); everything else is denied and logged.
Egress is on by default (`AUGUR_EGRESS=auto`), unrecognized values fail *on*, and the same
allowlist/enforcement contract is shared across both engines. The design principle is
**containment, not exfiltration-proofing** — a formally closed decision
([ADR-0008](../decisions/0008-exfiltration-ceiling-accepted.md)): keep an untrusted agent away
from arbitrary internet endpoints and off the host, using only mechanisms that never require
elevated privilege.

The shape is unchanged since 2026-07-20. What moved this cycle is **lifecycle**, not enforcement:
Apple Container mode now **persists** its container across `down`/`up` and reconciles on `up`
(mirroring macOS VM mode; [ADR-0010](../decisions/0010-container-persistence.md)), so the
security work was to keep the fail-closed guarantees green on the new *reuse* path — the boot
self-test now gates reuse as well as fresh create, and its probes are PATH-pinned so a persisted
guest can't shadow them. Two proxy-core changes landed, both additive and post-decision: an
**idle timeout** on established tunnels (#101, closing the prior snapshot's one open residual) and
an **I8 SSRF v6 guard** strengthening (6to4/Teredo/site-local). One host-side fix closed a real
**I7 TOCTOU** (honor the approved snapshot, not a post-approval live re-read). The same
fail-closed proxy/allowlist/TOFU machinery still also extends one layer earlier in the lifecycle —
to **building the shared base images** (§2.1) and **trusting an operator-supplied CA** (§2.2) —
under mechanisms that cannot touch or widen any live project's allowlist.

## 2. Enforcement boundary per engine (still two engines)

Both engines share the *same* merged allowlist and the *same* augur-proxy filter core; they
differ only in **where the proxy runs** and **how the guest is severed from direct egress**. Every
Apple Container and macOS VM enforcement element below was individually re-verified against current
code this snapshot. The enforcement *elements* are unchanged from 2026-07-20; what changed in
container mode is the lifecycle **shape** (persist-and-reconcile), not these elements.

### 2.1 Base-image custom provisioning (PR #78, unchanged)

An operator can pre-install extra packages into augur's *shared* base images at build time: a
Homebrew manifest for the macOS base VM (`~/.augur/provision/manifest.conf` + optional
`hook.sh`/`hook.allowlist.conf`) or an apt manifest for the Apple Container image
(`~/.augur/provision/container-packages.conf`). Both manifests are TOFU-gated (`tofu_decide`,
cache at `~/.augur/provision-hashes/`, separate from the per-project `~/.augur/project-hashes/`).
Inherits I1–I9 by construction. Its one new-in-kind residual (`hook.sh` is TOFU-gated executable
root content cloned into every VM) is unchanged — §6 item 11.

### 2.2 Custom CA trust (`augur install-cert`, unchanged)

A per-project operator command (PRs #88/#90) that trusts a single operator-supplied PEM CA in the
guest: on Apple Container it rebuilds the image with `AUGUR_CA_CERT_B64` baked in
(`update-ca-certificates` as root at build time, then dropped back to the unprivileged `dev`
user); on macOS it prompts a GUI keychain-trust dialog over SSH — manual-first on macOS 26, since
SSH-invoked keychain trust is unconditionally denied there without a GUI session. Gated by an
explicit, per-invocation `y/N` (`AUGUR_ACCEPT_CERT_INSTALL=1` non-interactive override) — a
one-shot operator action, not the persisted-hash TOFU model §2.1 uses. **Does not widen the egress
boundary or the proxy's trust model**: `augur-proxy` never terminates TLS (grep-clean of
`SSLContext`/`SecTrust`/X509 verification across `Sources/`), so a guest-trusted CA only affects
what the guest's *own* TLS clients accept post-tunnel — the proxy's by-hostname allow/deny decision
happens before that and is unaffected. **install-cert also invalidates the persisted container** so
a rebuilt image takes effect (`invalidate_persisted_container`, `augur:1226-1233`; see §2.3).

### 2.3 Container lifecycle: persist-and-reconcile (new this snapshot, #114)

Apple Container mode now persists its container across `down`/`up`, symmetric with macOS VM mode
([ADR-0010](../decisions/0010-container-persistence.md), superseding the Container half of ADR-0006):

- **`down` STOPS and keeps** the container + egress network (`cmd_down`, `augur:1602-1628`): it
  runs `eng stop "$CONTAINER_NAME"` and re-checks state instead of `container delete --force`, so
  the writable layer persists for a fast restart. It calls only `stop_proxy` and deliberately
  **not** `stop_egress`, so the routeless `--internal` network is kept for the next up to
  re-attach. The keep-alive PID 1 traps SIGTERM (`sh -c 'trap "exit 0" TERM; sleep infinity & wait'`,
  `augur:1506`). Keeping a routeless `--internal` network while stopped does **not** widen egress
  (no route to host/internet; the host proxy is stopped; no container is running).
- **`up` RECONCILES** (`cmd_up`, `augur:1319-1352`): if `container_exists && container_fingerprint_matches`,
  it re-ensures the network (idempotent) then `eng start`s the stopped container and returns via
  `finish_up`; if start fails it falls through to a clean recreate. `container_fingerprint`
  (`augur:1255-1301`) hashes exactly the inputs baked at `run` and unchangeable by `start`: egress
  on/off state + wiring (subnet / gateway-override / http-port), resolved memory, `WORKSPACE_DIR` +
  mount, **every resolved auth credential VALUE** (named-only, same source as the `-e` injection),
  gh token value, gitconfig-presence. Any drift (rotated/added/removed token, flipped egress mode,
  resized memory, moved workspace) forces a clean recreate, so a reused container never runs stale
  credentials or stale egress wiring. `--cap-drop NET_ADMIN` and `--no-dns` are not hashed literally
  but are deterministic consequences of egress being ON, which **is** hashed. Image CONTENT is
  out-of-band: build/update/install-cert call `invalidate_persisted_container` (`augur:1217,1226-1233`)
  so a rebuilt image always takes effect. The fingerprint FILE stores only a sha256 **digest**,
  written umask 077 (0600) host-side — not itself a recoverable at-rest secret.
- **`augur destroy`** (`cmd_destroy`, `augur:1633-1645`, dispatched `augur:3692`) is the full
  removal (container + network + fingerprint file). Because `down` no longer deletes, the A2
  clean-binary remedy for a tampered guest is now `augur destroy && augur up`, not `down && up`;
  `cmd_setup_token`'s integrity-failure message was updated accordingly (`augur:1563-1567`).

The load-bearing egress enforcement is host-side and re-established on every `up` regardless of
reuse: `--internal` severs routing, `--cap-drop NET_ADMIN` blocks re-routing, the allowlist proxy
runs on the host, and `verify_egress_locked` fires on every `up`. `cmd_claude`/`cmd_shell` route a
stopped/absent container through the full `cmd_up` (`container_running || cmd_up`, `augur:1530,1544`),
never a bare `container start`, so there is no silent reuse path that skips the self-test (the old
`ensure_running` bare-start path is gone, grep-clean). Covered by `tests/22_egress_failclosed.sh`
(runs the full fail-closed set **twice** — fresh AND reuse — asserting "Reusing stopped container"
+ "Egress self-test passed" on the reuse pass) and `tests/11_construct_container.sh` (offline
reconcile: reuse = `container start` on match, recreate = `delete --force` + `run` on memory drift).

## 3. augur-proxy filter internals (2 datapath changes since 2026-07-20, both additive)

Same two-listener architecture — HTTP CONNECT (Apple Container) + SOCKS5 (macOS VM) over one
shared `Filter`; a blind TCP tunnel, decision by hostname, never TLS-terminating. Verified 0
commits since base on `Allowlist.swift`, `Hostname.swift`, `Filter.swift`, `PinTable.swift`,
`SNI.swift`, `Logger.swift`, `ProxyRequests.swift`; `main.swift`/`ProxyServer.swift` edits are
confined to idle-timeout plumbing. Re-verified against current code:

- **Fail-closed startup** (`main.swift:114-119`) — unchanged: dies if `--allowlist` is empty or
  the path unset, dies if neither `--http-port`/`--socks-port` is set, `exit(2)` if
  `Allowlist.fromFile` returns nil. `publicOnly=true` by default (`main.swift:29`); only
  `--allow-private` clears it (`main.swift:68`) and remains grep-clean on every production path
  repo-wide (I1/I8).
- **Boundary-anchored matching** (`Allowlist.swift:82-88`) and **hostname validation**
  (`Hostname.swift:11-33`) — unchanged: `isSubdomain` still requires a label-boundary dot before

## 4. Three-layer allowlist config model + TOFU (I7 TOCTOU closed)

Union-only merge — each layer can *widen*, none removes a lower layer's entries:

1. **Managed baseline** `~/.augur/augur.conf.default` (`AUGUR_BASELINE_CONF`, `augur:48`) — copied
   verbatim from repo `augur.conf` on install.
2. **User global** `~/.augur/augur.conf` (`AUGUR_GLOBAL_CONF`, `augur:49`) — scaffolded once, never
   clobbered.
3. **Per-project** `./.augur/allowlist.conf` (`AUGUR_PROJECT_CONF`, `augur:54`) — merged
   **sanitized only** (via `project_conf_domains` / `conf_line_valid`).

`write_merged_allowlist` (`augur:603-628`) cats baseline + global verbatim (`augur:610-611`) and
appends only the **sanitized, approved project snapshot**, writing to
`~/.augur/proxy/<slug>.allowlist` (`proxy_allowlist`, `augur:590`) **outside the project mount** —
so a root-in-guest editing the mounted `./.augur/allowlist.conf` cannot rewrite the runtime policy
mid-session (I7).

**Closed this snapshot — the I7 TOCTOU (`f3c2d35`, hardened by `e565551`).** The honored project
block is no longer a *fresh live read* of the guest-writable mounted file at merge time; it is now
sourced from a host-side **approved snapshot** (`~/.augur/project-hashes/<slug>-<pathhash>.domains`,
`augur:607,619-625`) captured **atomically with the approval fingerprint** from a single stable
copy of the conf (`check_project_conf_approved`, `augur:853-874`). A missing snapshot **fails
closed** by omitting the project block (`augur:623`). This closes the check/use split that
previously let a race between approval and merge — most concretely across two concurrent engine
modes on one repo — get unapproved-but-grammar-valid domains honored (full analysis under "What
changed"). The snapshot is (re)written on every approval path including the already-approved fast
path (`augur:879-884`, healing pre-snapshot approvals), and `sha256(copy)==sha256(original)` so
existing approvals don't re-prompt on upgrade.

TOFU approval (`check_project_conf_approved`, `augur:839-924`) is keyed on `slug + full-workspace-path-hash`
(`augur:804-821`), so a hostile same-basename repo cannot inherit a trusted project's approval;
fails closed with no sha256 tool (`augur:862-866`); fails closed non-interactively without
`AUGUR_ACCEPT_PROJECT_CONF=1` (`augur:921-923`); prints the sanitized widening domains + a
dropped-line red-flag count and prompts `[y/N]`; and surfaces terminal-escape/obfuscation lines as
dropped. It runs on **every** `up` before the merge (`augur:1330` container / `augur:2232` macOS),
including the **container-persist reuse path** (`finish_up`, `augur:1306-1317`), so a project conf
mutated between sessions is re-fingerprinted and caught — the persist feature does not create a
stale-approval bypass. `conf_line_valid` (`augur:636-651`) enforces strict LDH / charset (mirrors
the proxy's `isValidHostname`) on every project line, so only clean patterns reach both the
approval display and the merged policy, and the displayed list is identical to what the proxy honors.

## 6. Known limitations & residual exfil channels

The threat model is *"contain a prompt-injected agent away from its host,"* **not** *prevent exfil
through a legitimately allowlisted, credentialed host*. Every carried-forward residual from
2026-07-20 (items 1–18) still holds; the container-persistence work (#114/#115) adds four genuinely
new residuals (20–23) and widens the M1 credential residual (item 6); item 19 (no idle timeout)
**closes**.

1. **Allowlisted + credentialed host is an in-policy exfil surface — a closed, permanent
   decision.** `github.com` allowlisted + a full-scope `GH_TOKEN` injected → an injected agent can
   push data to an attacker repo entirely within policy.
   [ADR-0008](../decisions/0008-exfiltration-ceiling-accepted.md) (issue #24, closed) declines to
   mitigate this by default or opt-in — not TLS MITM/DLP, not per-service authorization, not the
   lighter `--no-token`/read-only-mount middle ground. Users who need this belong on dedicated
   DLP/CASB/enterprise egress tooling alongside augur, not inside it.
2. **Wildcard / QNAME tunneling.** A broad wildcard (e.g. `*.githubusercontent.com`) permits
   `<data>.<wildcard>` leakage; mitigation is allowlist policy, not the matcher.
3. **Apple Container `0.0.0.0` host-reach (accepted trade-off).** Host-only `--internal` lets the
   guest reach other host services bound to `0.0.0.0` (raw TCP, not proxy-mediated) — weaker than
   an isolated network. A direct consequence of the no-sudo constraint (closing it needs host `pf`
   = sudo); documented, not enforced, effectively **permanent** ([ADR-0001](../decisions/0001-sudo-free.md),
   which also records that an `augur up` exposure warning was prototyped, measured, and declined).
   **Unchanged by persistence** — host-reach happens while attached; keeping the network across
   `down` doesn't alter it.
4. **No-sudo consequences ripple through the datapath.** "Never require sudo" took priority over
   stronger isolation, forcing host-only + host-side proxy (Apple) and `VZFileHandle` + gvproxy
   SOCKS (VM). Provisioning, `install-cert`, and the persist-and-reconcile reshape all extend the
   same principle rather than relaxing it.
5. **TOFU auto-accept widens non-interactively.** `AUGUR_ACCEPT_PROJECT_CONF=1` /
   `AUGUR_ACCEPT_PROVISION_HOOK=1` / `AUGUR_ACCEPT_CERT_INSTALL=1` widen without operator review
   (used by CI / non-interactive runs).
6. **Credentials on Apple Container `container run -e` argv (M1) — now also at rest in a
   longer-lived config.** `ANTHROPIC_API_KEY` / `CLAUDE_CODE_OAUTH_TOKEN` / `GH_TOKEN` are visible
   to a co-resident host process via `ps`/`/proc` **while running** (unchanged). **New:** because
   `down` now keeps the container, those baked `-e` values persist at rest in the container's config
   for its whole lifetime — the M1 window widens from session-duration to until-`destroy` (or a
   fingerprint-mismatch recreate). The reconcile fingerprint reads the resolved secret VALUES so a
   rotated token forces a clean recreate on the next `up` (bounding staleness), but stores only a
   sha256 **digest** umask-077 (`augur:1277-1288`) — the fingerprint file is not itself a
   recoverable at-rest secret; `destroy` clears the container copy. Accepted Low under the
   single-user premise; **resurfaces on a shared host**. macOS still routes secrets through
   `~/.augur-env` chmod 600 via SSH stdin, never on argv ([ADR-0007](../decisions/0007-macos-build-fixed-credential.md)).
7. **Basename-only slug collisions for the egress network / subnet / ports (~1/900) — container/VM
   names now fixed.** `make_container_name` now embeds `workspace_path_hash` (`augur:244-251`), so
   two same-basename projects can no longer resolve to — and thus **reuse** — the same persisted
   container (this matters *specifically* because `down` now keeps the container: without the hash,
   project B's up/claude could re-attach to project A's persisted container with A's mounts,
   credentials, and any foothold). But `egress_network_name` (`augur-<slug>-net`, `augur:994`) and
   the subnet/ports (`augur:65-78`) remain **basename-derived**. Two bounded, non-egress-widening
   consequences per ADR-0010: a same-basename `augur destroy` can delete the shared
   `augur-<slug>-net` a *different* project's kept-stopped container is still attached to
   (self-heals on that project's next `up`, which recreates the network), and toggling `--no-egress`
   on a recreate can momentarily orphan the kept `--internal` network. Neither widens egress — the
   network is routeless and the allowlist is host-side, regenerated per `up`. Old item 7 partially
   improved (name fixed), not fully closed (subnet/ports remain).
8. **Every "accepted" residual assumes a single-user host.** On a shared host / CI runner, the argv
   + at-rest secret exposure, name/network collisions, and cross-tenant reach all resurface. This
   now specifically covers the persisted-foothold trade (items 20–21).
9. **Fail-closed edges are hard errors, not graceful.** Proxy readiness is a fixed ~2 s poll and
   gateway-iface readiness waits ≤5 s; on slow bring-up the bind can fail and `exit 1`.
10. **Compatibility limits (fail-closed).** No-SNI (ECH/ESNI, non-TLS/non-HTTP) and IPv6/IP-literal
    connects are denied. augur's needs are all HTTPS, so this is accepted.
11. **hook.sh is TOFU-gated *executable root content*, not a data file.** `run_provision_hook` runs
    an arbitrary root script once approved; its blast radius is every VM cloned from the base image.
    Unchanged.
12. **[HIGH — inherent to the model] RW workspace mount → host code execution via `.git/hooks`.**
    `WORKSPACE_DIR=$(pwd)` is bind-mounted **read-write** into the guest. A prompt-injected guest
    can plant `.git/hooks/pre-commit` (or similar); the next **host**-side `git` operation in that
    repo executes guest-authored code at the user's full host privilege — a complete escape of both
    the container/VM boundary and the egress allowlist. The single highest-impact residual; mitigation
    is entirely out-of-band (review diffs, treat `.git/hooks` as attacker-controlled). Documented in
    the README. **Unchanged by persistence.**
13. **[LOW, fixed] macOS `~/.augur-env` secret interpolation validated** (`validate_secret_value`).
    Confirmed present.
14. **[LOW, fixed] `resources.conf` values clamped**, incl. the 64-bit-multiply-overflow follow-up.
    Confirmed present.
15. **[Superseded by a stronger fix] Whole `~/.claude.json` scp on macOS.** The real file is never
    read or copied at all — a static onboarding stub is seeded instead (#90). No residual.
16. **[LOW, fixed] `verify_egress_locked` IPv6-literal probe added.** Confirmed present (commit is
    an ancestor of HEAD).
17. **[LOW] Apple Container proxy opens both listeners.** Unchanged — in container mode the proxy
    binds the guest-facing gateway and opens both HTTP and SOCKS listeners though only HTTP is used.
    Avoidable surface, not a bypass. The idle-timeout change does not alter it. *Still deferred.*
18. **[LOW — hygiene] macOS base-VM sudo-revoke is branch-coordinated and untested.** Unchanged.
    *Still deferred.*

### Closed since 2026-07-20

19. **[CLOSED] No idle timeout on established (spliced) tunnels (was §6 item 19 / issue #101).**
    The 2026-07-20 snapshot's single "new this review" residual — a guest holding an
    already-established tunnel open-and-idle to pin up to `--max-connections` slots — is now bounded
    by the shared-activity idle timeout (`f5af0fb`: `IdleTimeout.swift` `IdleTracker` + classifiers
    wired into the splice loop, default 900 s ON, tunable via `--idle-timeout` /
    `AUGUR_PROXY_IDLE_TIMEOUT`). Both read (`SO_RCVTIMEO`) and write (`SO_SNDTIMEO`) sides are
    bounded (a stopped-reading guest can't pin a slot via a blocked write), and idle expiry tears
    down both fds jointly so the peer thread releases its slot promptly. Issue **#101 closed**. The
    **trickle case** — a ≥1-byte-per-window tunnel is never reaped — remains, by design: such a
    tunnel is by definition ACTIVE (the same property that correctly preserves a low-traffic
    SSE/long-poll stream), and it stays bounded to `--max-connections` slots. Accepted trade-off,
    not a hole (`IdleTimeout.swift:15-20`).

### New this review

20. **Persisted writable-layer foothold survives `down`/`up` (Container mode).** `down` =
    `container stop` keeps the writable layer, so a compromised guest's tampered filesystem now
    persists across `down`/`up` in Container mode (the "disposable guest" was Container-mode-only).
    Reset only by `augur destroy` or a fingerprint-mismatch recreate. This is the **same class**
    ADR-0004 §7 / ADR-0006 already accepted for macOS VM mode — Container mode now carries it too;
    a deliberate trade for fast restarts, bounded by `destroy` and the setup-token A2 integrity gate.
    Does **not** widen egress — the network controls are container-create-time and re-applied by
    `start`, the allowlist is host-side and regenerated per `up`, and the I1 self-test runs on every
    reuse. The path-hash-keyed container name keeps the foothold from leaking to a different project
    (item 7).
21. **Reuse-path boot self-test runs inside a possibly-tampered guest.** `verify_egress_locked` runs
    on **every** `up` via `finish_up`, including the fingerprint-match reuse path — the datapath is
    rebuilt per up, never cached, so I1's tripwire still fires. But on reuse the probes
    (`curl`/`getent`) execute inside a container whose writable layer a prior uid-1001 session could
    have modified, so they are no longer a **fully independent** tripwire the way they are against a
    pristine image. **Mitigated:** every probe is pinned to `-e PATH=/usr/bin:/bin:/usr/local/bin`
    (`augur:1089`), excluding the dev-writable `~/.local/bin` that is first in the image PATH
    (`Dockerfile:48`), so the non-root uid-1001 guest (`Dockerfile:41,90`) cannot shadow
    `curl`/`getent` to fake isolated answers. **Not eliminated:** a hypothetical
    container-escape-to-root guest could still tamper with `/usr/bin`. **Crucially the REAL
    enforcement is host-side** (`--internal` severs routing, `--cap-drop NET_ADMIN`, the host-side
    allowlist), all re-applied by `container start` and independent of the guest — a shadowed
    self-test blinds *detection*, it does not open egress (ADR-0010 §Rationale-2).
22. **Per-project agents mount — guest can plant subagent defs into its own project dir (state, not
    egress).** #115 mounts `~/.augur/claude-agents/<slug>-<pathhash>` at the guest
    `~/.claude/agents` (`augur:1461-1470`), keyed `slug + full-path-hash`, **outside** the host's
    own `~/.claude`. A compromised guest can plant a `/agents` subagent def only into its **own**
    project's host dir — never the host's real `~/.claude/agents` (so the host's own Claude Code
    never loads a guest-forged subagent) nor another project's. Same within-project trade-off as
    history; **not global**. Nuance: this dir is untouched by `down` **and** by `destroy`, so a
    planted def (like a forged transcript) survives even a full `destroy` and re-mounts into a
    from-scratch container — only manual host-dir deletion clears it. A state channel, not the egress
    datapath; I7 unaffected (the allowlist is separate and host-side).
23. **6to4/Teredo/site-local reachability is ≈ nil (defense-in-depth, not a demonstrated breach).**
    The `09c5ea5` v6 additions close a theoretical fall-through (an allowlisted name resolving to a
    6to4-wrapped `127.0.0.1`) rather than a demonstrated bypass — these prefixes are deprecated /
    unrouted-by-default / encapsulation, so real-world reachability is near zero. Recorded as
    completeness/consistency with the v4 side, not an urgent fix.

### Summary
Egress control is unchanged in **shape** since 2026-07-20 — a **host-side, fail-closed, sudo-free
domain-allowlist scheme shared by two engines** (Apple Container + macOS VM), on by default, with a
union-only three-layer merge, TOFU approval, and a Swift filter core — all **re-verified green
(54/54 Swift, all offline shell tiers incl. 35/35 for I7, 27/27 structural macOS-VM checks)** on
2026-07-23. What moved this cycle is **lifecycle**, not enforcement: Apple Container mode now
**persists** across `down`/`up` and reconciles on `up` (ADR-0010), and the security work was to keep
the fail-closed guarantees green on the new reuse path — the I1 boot self-test now gates reuse as
well as fresh create, with PATH-pinned probes so a persisted guest can't shadow the tripwire, and
the load-bearing enforcement stays host-side and independent of the guest. Two additive proxy-core
changes landed: an **idle timeout** on established tunnels (#101 — **closing the prior snapshot's one
open residual**) and an **I8 SSRF v6 guard** strengthening (6to4/Teredo/site-local), neither
touching the allow/deny decision. One host-side fix closed a real **I7 TOCTOU** — the honored
project allowlist is now the approved host-side snapshot, not a post-approval live re-read. The
persistence reshape adds four accepted residuals (persisted writable-layer foothold, a reuse-path
self-test no longer fully independent, a per-project agents state mount, and a still-basename-keyed
egress network/subnet/ports) and widens the M1 credential residual to at-rest in the kept container;
all are bounded, non-egress-widening, and framed by the single-user-host premise. The
**RW-workspace `.git/hooks` host-code-execution path** (§6 item 12) remains the single highest-impact
residual, unchanged. **No invariant (I1–I10) changed status and no invariant TEXT changed this
snapshot** (`INVARIANTS.md` diff against base is empty); four invariants (I1, I5, I7, I8) had their
*implementation* strengthened within their existing prose.
