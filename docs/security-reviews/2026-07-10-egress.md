## 1. Essence

augur egress control is a **host-side, fail-closed, on-by-default domain allowlist** that
confines a possibly prompt-injected coding agent (Claude Code today), running on a trusted
single-user host, by forcing *all* guest outbound traffic through **augur-proxy** — a
dependency-free Swift forward proxy that runs as the ordinary host user **with no sudo**. The
guest is severed from direct egress and its only route out is the proxy, which re-resolves
each connection **by hostname** and admits it only if it matches a **union-only, three-layer
domain allowlist** (managed baseline + user-global + per-project); everything else is denied
and logged. Egress is on by default (`AUGUR_EGRESS=auto`), unrecognized values fail *on*, and
the same allowlist/enforcement contract is shared across both engines. The design principle is
**containment, not exfiltration-proofing**: keep an untrusted agent away from arbitrary
internet endpoints and off the host, using only mechanisms that never require elevated
privilege. The same fail-closed proxy/allowlist/TOFU machinery is also extended one layer
earlier in the lifecycle — to **building the shared base images** (§2.1) — under a dedicated
proxy identity that cannot touch or widen any live project's allowlist.

## 2. Enforcement boundary per engine (now two engines)

Both engines share the *same* merged allowlist and the *same* augur-proxy filter core; they
differ only in **where the proxy runs** and **how the guest is severed from direct egress**.

| Engine | Proxy placement | Guest containment | Strength | Specific weakness |
|---|---|---|---|---|
| **Apple Container (host-only, primary)** | augur-proxy runs **on the host**, bound to the **host-only gateway IP** (not `0.0.0.0`), started *after* the container attaches (`start_egress_proxy`) | Agent on a per-project `--internal` (host-only) network; `--cap-drop NET_ADMIN` (root agent can't re-route); `--no-dns` (empty resolv.conf); `HTTP(S)_PROXY`→gateway IP. Boot self-test `verify_egress_locked` tears the container down on any leak | Sudo-free; `--no-dns` confirmed live on macOS 26; gateway-bind keeps the proxy off the physical LAN; the boot self-test is a live tripwire | **Host-only `--internal` lets the guest reach other host services bound to `0.0.0.0`** (raw TCP, not proxy-mediated) — weaker than an isolated network. Documented, **not enforced**; closing it needs host `pf`/sudo, which augur declines (§6 item 3) |
| **macOS VM (gvproxy)** | augur-proxy runs on **`127.0.0.1`** (SOCKS5); the VM's only NIC is a host-owned `AF_UNIX`/`SOCK_DGRAM` socket into **gvproxy** (forked gvisor-tap-vsock), which forwards all guest TCP to the proxy's SOCKS port by dest IP | User-space netstack: guest has no host-routable IP; `--deny-direct` drops UDP/ICMP *and* the guest-facing forwarder-management HTTP mux (port 80); `--dns-allowlist` gates DNS (A/AAAA/CNAME only; TXT/MX/NS/SRV refused); runt-frame drop guards the rx goroutine; only the ad-hoc-signable `com.apple.security.virtualization` entitlement (no `com.apple.vm.networking`) | Fully sudo-free VM egress with no privileged bridged-networking entitlement; SOCKS-filtered TCP is the sole egress; hermetic SSH (`-F /dev/null`) blocks host-env leak; `--dns-allowlist` is a byte-parity Go port of the Swift `Allowlist`/`Hostname` matcher, unit-tested incl. the NUL-truncation case | **No in-guest boot self-test** (`verify_egress_locked` is Apple-Container-only); relies on `--deny-direct`/`--dns-allowlist` + SSH liveness. Depends on an **external forked gvproxy process**. Validated only manually on Apple Silicon (structural/entitlement checks are CI-covered; live NIC-count / UDP-ICMP-drop are not — §5) |

### 2.1 Base-image custom provisioning (PR #78, unchanged this snapshot)

An operator can pre-install extra packages into augur's *shared* base images at build time: a
Homebrew manifest for the macOS base VM (`~/.augur/provision/manifest.conf` + optional
`hook.sh`/`hook.allowlist.conf`) or an apt manifest for the Apple Container image
(`~/.augur/provision/container-packages.conf`). On macOS this runs once, as root, inside the
base-VM build, routed over a **dedicated** egress-filtered proxy/gvproxy pair with fixed ports
(`13999/14999/20999`) structurally disjoint from any per-project instance. On Apple Container
the image build already runs with zero egress filtering (pre-existing design), so
`container-packages.conf` is only validated + TOFU-gated and passed as a `--build-arg`. Both
manifests are TOFU-gated (`tofu_decide`, cache at `~/.augur/provision-hashes/`, separate from
the per-project `~/.augur/project-hashes/`). Inherits I1–I9 by construction. Its one
new-in-kind residual is that `hook.sh` is TOFU-gated **executable root content** cloned into
every VM (§6 item 12). The brew-PATH reliability fix for this feature has now landed (see the
change-log above), so the earlier "ships without its own author's fix" caveat no longer holds.

## 3. augur-proxy filter internals (re-verified, no logic change)

Dependency-free, cross-platform SwiftPM package — POSIX sockets only. Two listeners over one
shared allowlist: an HTTP CONNECT/forward proxy (Apple Container datapath) and a SOCKS5 server
(macOS VM / gvproxy datapath). It is a **blind TCP tunnel — never TLS-terminating**; the
decision is **by hostname**.

- **Fail-closed startup** (`main.swift`): dies if `--allowlist` is empty, dies if neither
  `--http-port`/`--socks-port` is set, `exit(2)` if `Allowlist.fromFile` returns nil
  (unreadable / non-UTF-8) — refuses to start without a readable policy (I1). `publicOnly=true`
  by default; only `--allow-private` clears it, and it is **never passed on any production
  path** (grep-clean, incl. the provisioning path) (I8).
- **Boundary-anchored matching** (`Allowlist.swift`): `*.x`→subdomains only, `.x`→apex + subs,
  bare `x`→apex only. `allows()` lowercases, strips port + one trailing dot, rejects IP literals
  and any host failing `isValidHostname`, then exact membership else `isSubdomain` (a `.` at the
  label boundary) — so `*.github.com` matches `api.github.com` but **not** `evilgithub.com` or
  `github.com.evil.com` (I2, tested).
- **Hostname validation / NUL defense** (`Hostname.swift`): strict LDH on UTF-8 bytes, ≤253
  total, per-label 1–63, rejects empty labels and NUL/space/underscore — the same string that
  is matched is the one dialed, closing `evil.com\0.github.com` (I3).
- **IP-literal deny + dead PinTable** (`Filter.swift`, `PinTable.swift`): the pin table that
  could re-allow a recently-resolved IP has **no production caller** (grep-clean), so every
  IP-literal connect is denied unconditionally (I4).
- **SNI re-decide + re-dial by name** (`ProxyServer.swift`): SOCKS5 receives an IP-literal from
  gvproxy, peeks the TLS SNI / HTTP `Host`, re-decides, and re-dials **by the peeked name** —
  a spoofed SNI cannot exfil elsewhere; no recoverable name → `deny("no-sni")`.
- **Dial-time SSRF guard** (`SocketIO.swift`, `AddressPolicy.swift`): under `publicOnly` the
  connect skips any resolved address classified non-public (RFC1918, loopback, CGNAT
  `100.64/10`, link-local incl. metadata `169.254.169.254`, IPv4-mapped v6, NAT64, ULA,
  multicast); unknown family refused (I8).
- **Hot reload never falls open** (`main.swift`, `Filter.swift`): 2 s mtime poll; a successful
  parse (even empty = deny-all) is swapped atomically under lock; an unreadable file **keeps the
  previous policy** (I6).
- **Deny logging** (`Logger.swift`): one greppable `DENY client=… dst=host:port reason=…` per
  block (`not-in-allowlist`, `ip-literal`, `no-sni`, `upstream-unreachable`).

## 4. Three-layer allowlist config model + TOFU (unchanged)

Union-only merge — each layer can *widen*, none removes a lower layer's entries:

1. **Managed baseline** `~/.augur/augur.conf.default` — copied verbatim from repo `augur.conf`
   on every install.
2. **User global** `~/.augur/augur.conf` — scaffolded once, never clobbered.
3. **Per-project** `./.augur/allowlist.conf` — merged **sanitized only** (via
   `project_conf_domains` / `conf_line_valid`).

`write_merged_allowlist` cats baseline + global verbatim, appends only sanitized project
domains, and writes to `~/.augur/proxy/<slug>.allowlist` **outside the project mount** — so a
root-in-guest editing the mounted `./.augur/allowlist.conf` cannot widen its own policy
mid-session (I7). TOFU approval (`check_project_conf_approved`) fingerprints the project conf
(fails closed if no hash tool), prints sanitized widening domains + prompts `[y/N]`, and stores
approvals host-side keyed on the **full workspace path** (never mounted, so the guest can't
forge them). A sibling `./.augur/resources.conf` (CPU/memory sizing) is **not** an egress
control and carries no TOFU gate by design — see §6 item 14 for the (new) unbounded-value note.

**Current default baseline set — unchanged, 18 patterns**: Claude Code runtime
(`api.anthropic.com`, `.claude.ai`, `.claude.com`, `*.anthropic.com`, `statsig.anthropic.com`,
`statsig.com`, `*.statsig.com`, `sentry.io`, `*.sentry.io`); GitHub (`github.com`,
`api.github.com`, `codeload.github.com`, `objects.githubusercontent.com`,
`raw.githubusercontent.com`, `*.githubusercontent.com`); Homebrew/ghcr (`formulae.brew.sh`,
`ghcr.io`, `*.ghcr.io`).

## 6. Known limitations & residual exfil channels

The threat model is *"contain a prompt-injected agent away from its host,"* **not** *prevent
exfil through a legitimately allowlisted, credentialed host*.

1. **Allowlisted + credentialed host is an in-policy exfil surface.** `github.com` is
   allowlisted and a full-scope `GH_TOKEN` is injected → an injected agent can push data to an
   attacker repo entirely within policy. Out of model.
2. **Wildcard / QNAME tunneling.** A broad wildcard (e.g. `*.githubusercontent.com`) permits
   `<data>.<wildcard>` leakage; mitigation is allowlist policy, not the matcher.
3. **Apple Container `0.0.0.0` host-reach (accepted trade-off).** Host-only `--internal` lets
   the guest reach other host services bound to `0.0.0.0` — weaker than an isolated network. A
   direct consequence of the no-sudo constraint (closing it needs host `pf` = sudo); documented,
   not enforced, effectively **permanent**.
4. **No-sudo consequences ripple through the datapath.** "Never require sudo" took priority over
   stronger isolation, forcing host-only + host-side proxy (Apple) and `VZFileHandle` + gvproxy
   SOCKS (VM). Provisioning extends the same principle rather than relaxing it.
5. **TOFU auto-accept widens non-interactively.** `AUGUR_ACCEPT_PROJECT_CONF=1` /
   `AUGUR_ACCEPT_PROVISION_HOOK=1` widen without operator review (used by CI).
6. **Credentials on Apple Container `container run -e` argv (M1).** `ANTHROPIC_API_KEY` /
   `CLAUDE_CODE_OAUTH_TOKEN` / `GH_TOKEN` are visible to a co-resident host process via
   `ps`/`/proc`. Accepted Low under the single-user premise; **resurfaces on a shared host**.
   (macOS writes them to `~/.augur-env` chmod 600 via SSH stdin, never on argv.)
7. **Basename-only slug collisions (~1/900).** Approval-hash and history dirs are full-path-keyed,
   but container/VM names and egress ports/subnet remain basename-keyed, so two same-basename
   projects running concurrently collide on ports/subnet; recovery is a manual override.
8. **Every "accepted" residual assumes a single-user host.** On a shared host / CI runner, the
   argv secret exposure, name collisions, and cross-tenant reach all resurface.
9. **Fail-closed edges are hard errors, not graceful.** Proxy readiness is a fixed ~2 s poll and
   gateway-iface readiness waits ≤5 s; on slow bring-up the bind can fail and `exit 1`.
10. **Compatibility limits (fail-closed).** No-SNI (ECH/ESNI, non-TLS/non-HTTP) and IPv6/IP-
    literal connects are denied. augur's needs are all HTTPS, so this is accepted.
11. **hook.sh is TOFU-gated *executable root content*, not a data file.** `run_provision_hook`
    runs an arbitrary root script (`sudo bash …`) once approved; its blast radius is every VM
    cloned from the base image. A single mistaken approval poisons every subsequent clone until
    the next `augur update --macos`/rebuild. Weigh a `hook.sh` diff accordingly.

### New this review

12. **[HIGH — inherent to the model] RW workspace mount → host code execution via `.git/hooks`.**
    `WORKSPACE_DIR=$(pwd)` is bind-mounted **read-write** into the guest (`-v` on Apple
    Container; virtiofs `--dir` on macOS). The tree includes `.git`, so a prompt-injected guest
    can plant `.git/hooks/pre-commit` (or `post-checkout`, `post-merge`, …). Git runs repo-local
    hooks with **no trust prompt**, so the next time the **host** user runs any `git` operation
    in that repo, guest-authored code executes **on the host at the user's full privilege** — a
    complete escape of both the container/VM boundary and the egress allowlist. The same shape
    applies to any repo file the host later auto-trusts (`Makefile`, `mise.toml`, `.envrc`/direnv),
    though those usually need a host-side trust step that git hooks do not. This is **inherent to
    augur's core model** (mount the repo RW for an agent) and is the **single highest-impact
    host-reach path**; mitigation is entirely out-of-band (the human reviews diffs / trusts their
    own repo, and treats `.git/hooks` in an augur-touched repo as attacker-controlled until
    inspected). Previously noted only in a worktree/history context
    (`docs/claude-worktree-support-design.md`, the 2026-06-28 review); **elevated here to the
    top-level residual register** because it applies to the main checkout too.
13. **[LOW] macOS `~/.augur-env` secret interpolation is unvalidated (shell-injection edge).**
    `cmd_up_macos` writes `export VAR='<value>'` into a sourced shell file, but the per-secret
    validator (`agent_auth_specs`) is `none` today. A secret from `~/.anthropic_api_key`, the
    host env, or a doctored `gh` containing a single quote / control byte breaks the quoting and
    injects shell into `~/.augur-env`, run in every guest zsh. In-code this is the flagged "C3"
    future-work item. Container mode is unaffected (argv, not a shell). *Fix in flight (F2).*
14. **[LOW] `resources.conf` values are unbounded (guest-influenced host DoS).** The guest-
    writable, deliberately un-TOFU'd `./.augur/resources.conf` passes `MEMORY`/`MACOS_CPU`/
    `MACOS_MEMORY_MB` unvalidated to `container --memory` / `augur-vm set`; a value like
    `MEMORY=9999g` over-commits the host or fails the boot on the next `augur up`. No shell-
    injection (single quoted argv), no egress impact. *Fix in flight (F4).*
15. **[LOW] Whole `~/.claude.json` scp on macOS can carry MCP-server secrets.** `cmd_up_macos`
    scp's the entire file, characterized elsewhere as "onboarding state only — not auth"; but
    `~/.claude.json` also stores user-configured `mcpServers` whose `env`/`args` can hold
    third-party API keys — so more than the three named creds can transit into the macOS guest.
    macOS-only. *Fix in flight (F3).*
16. **[LOW] `verify_egress_locked` has no IPv6-literal probe.** The direct-egress tripwire hits
    only IPv4 literals; a v6 leak would be invisible to it (though `--internal`/`--no-dns` sever
    v6 and the proxy denies IP literals). *Fix in flight (F5).*
17. **[LOW] Apple Container proxy opens both listeners.** In container mode the proxy binds the
    guest-facing gateway and opens **both** HTTP and SOCKS listeners though only HTTP is used —
    avoidable surface, not a bypass (SOCKS still enforces the allowlist). *Fix in flight (F6).*
18. **[LOW — hygiene] macOS base-VM sudo-revoke is branch-coordinated and untested.** The
    build-time `NOPASSWD:ALL` grant is revoked across three sites; correct today but with no
    regression test. Impact is low (the macOS guest is already root-equivalent via fixed
    `admin/admin`). *Optional fix (F7).*

### Summary
Egress control is a **host-side, fail-closed, sudo-free domain-allowlist scheme now shared by
two engines** (Apple Container + macOS VM), on by default, with a union-only three-layer merge,
TOFU approval, and a Swift filter core (boundary matching, NUL defense, SNI re-decision,
unconditional IP-literal deny, SSRF guard, non-fail-open hot reload) — all **re-verified green
(38/38 Swift, 29/29 shell I7, structural macOS-VM checks)** on 2026-07-10. The headline change
is the **complete removal of Docker** (PR #82): the sidecar datapath is gone and the model
collapses to host-only-network + host-side proxy (Apple) and single-NIC + gvproxy SOCKS (VM).
Two prior open items are now closed (the provisioning brew-PATH fix landed; the gvproxy runt-
frame guard is shipped). The intentional residual surfaces carried forward — Apple host-only
`0.0.0.0` reach, in-policy exfil via an allowlisted credentialed host, macOS containment lacking
a CI gate, secrets on the container-run argv — are unchanged. The one **newly elevated** risk is
the **RW-workspace `.git/hooks` host-code-execution path** (§6 item 12), the fundamental limit of
"mount the repo for an agent," plus a cluster of low-severity hardening deltas (items 13–18)
being closed in a follow-up PR.
