## What changed in the contract

`git diff --stat 75e76e0..db5486f -- docs/security-reviews/INVARIANTS.md` is +22/−12, confined to I1's
`Enforced by` and I10's Rule and `Enforced by`:

- **I1, `Enforced by`.** The two host records of a macOS VM's boot (`macos_egress_mode_file`,
  `macos_egress_verified_file`) are one, `macos_boot_record_file` (`<slug>-<hash>.boot-record`, one
  line `<egress mode> <pass>`). The record is rewritten with no pass before every `augur-vm run`, its
  pass is dropped by the unverified-VM teardown, it is removed by `down`/`destroy`, and the pass is
  written only after the self-test passes. The pass is tied to the boot by `macos_vm_run_id`: the
  random UUID augur-vm's `run` writes to `run.id` plus the start time of the process in `run.pid`,
  read in UTC; it is read before the self-test and again before the pass is recorded, and the pass is
  recorded only when both agree.
- **I10, Rule.** A guest whose drop-in holds, comments and blank lines aside, anything but exactly
  augur's one `AcceptEnv` line is refused before any credential is sent (`macos_session_env_check_cmd`).
- **I10, `Enforced by`.** The clones' own check in the pre-save re-check is described the same way (an
  extra `AcceptEnv` or other directive, comments only or an empty file refused; an earlier install's
  comment line accepted).

## What the code now does for I1 and I10 (at `db5486f`)

**I1 (macOS half).**
- **One boot record.** `macos_record_egress_mode` writes `<mode> -` through one temp-file-and-rename
  writer (`macos_write_boot_record`) on every boot, **before** `start_proxy` / `start_gvproxy` and
  `augur-vm run`, so a record that cannot be written stops the boot with nothing started.
  `macos_read_boot_record` treats a missing or unparseable record (including the two files an older
  augur kept, which are not read) as no mode, and the VM is refused as one of unknown egress mode with
  the restart remedy; `down`/`destroy` also remove those two old files (`macos_remove_old_records`).
- **Run id bound to the boot and the process.** `macos_vm_run_id` is `<uuid> <lstart>`, empty when
  either part is missing. The UUID catches a hand-started `augur-vm run` that gets the old boot's pid
  within the same second; the start time catches a pid an unrelated process took after a host crash,
  when `run.pid`, `run.id` and the boot record all survive.
- **No pass for an untested boot.** `macos_selftest_and_record` is the one way `cmd_up_macos` runs the
  self-test on both paths: it reads the run id, runs `verify_macos_egress_locked`, and calls
  `macos_record_egress_verified` with that id. The pass is recorded only when the second read agrees;
  a VM booted again during the self-test gets none. On a running VM, a failed first read keeps a pass
  already recorded for the boot still running (it returns 0 with a warning). The pass is written with
  the record's own mode, and not at all when the record is gone at that read (a concurrent
  `down`/`destroy`). The read and the write take no lock, so a `down`/`destroy` landing between them
  can still see the record written again (dropping a pass has the same window): an `Accepted
  trade-off` in the code, since it needs two augur commands on the same project at once, which augur
  does not support. On a boot whose pass cannot be recorded, the teardown is
  `stop_macos_vm_and_egress` (the VM, gvproxy, proxy); `macos_record_egress_verified` alone owns the
  pass. `macos_selftest_and_record` takes that failure action itself and both call sites run it as a
  plain statement, so `set -e` applies throughout the self-test: a command failing in it unguarded
  ends `up` with no pass recorded (test 51).
- **The self-test's transport.** `verify_macos_egress_locked` pins the VM's SSH transport once
  (`macos_ssh_pin`, a module-level pin keyed by the VM) before its first probe and unpins it before its
  verdict; `ssh_macos` takes a transport only from that pin, never from a caller's variables.
  `_macos_ssh_cmd` exits on any failure to build a transport. The probes and the verdict are unchanged.

**I10 (macOS half).**
- **Drop-in check.** `macos_session_env_check_cmd` is
  `[ "$(grep -v -e '^[[:space:]]*#' -e '^[[:space:]]*$' <drop-in> 2>/dev/null)" = '<line>' ]`: comment and
  blank lines are ignored, the rest must be exactly augur's line, and a file with no line left (missing,
  empty, comments only) compares unequal. The same command is the push's first step and part of the
  pre-save re-check. The install writes the line alone; drop-ins #278's install wrote (a comment line,
  then the line) pass.
- **Credential names.** `session_credential_names` and the loop in `resolve_session_credentials` that
  builds `_creds` check each name (`credential_name_ok`); `macos_session_env_names` and
  `macos_session_env_delivery_cmd` check again as they write names into guest shell code, and a failure
  there stops the session before any ssh. `macos_env_add_export` keeps its own check.
- **Push refusal marker.** The push's guest side prints `AUGUR_SESSION_ENV_REFUSED`
  (`MACOS_PUSH_REFUSED_MARKER`) when the acceptance check fails, apart from the later steps' exit status;
  the content goes to ssh from a here-string. The return contract (1 / 2 / 3) and the messages are
  unchanged; a connection that drops after the guest has refused now still refuses.
- Unchanged: the values travel only as the session ssh's environment (`ssh_macos_session`), never on
  argv or the guest's disk; `~/.augur-env` holds no credential.

## Residual risks

- **Run-id stability (narrowed from 2026-11-08).** 2026-11-08 recorded that the self-test record rests
  on an unobserved `run.pid` stability and `ps -o lstart` stability. The id now adds augur-vm's per-boot
  UUID, so a hand-started `augur-vm run` that gets the old pid no longer matches even within the same
  second, and the before/after reads close the window in which a boot replaced during the self-test
  could inherit its pass. What remains: `ps -o lstart` printing one value for the process for the whole
  boot (across host sleep and clock syncs) is still unobserved on a Mac; a change would refuse sessions
  until `up --macos`, never admit one.
- **`run.id` is not yet observed on a Mac.** The Swift change (`RunSession.writePidfile` writes
  `UUID().uuidString` to `run.id` before `run.pid`; `cleanup()`, `stop`'s force-kill and `clone` remove
  it) has not been built: augur-vm is Darwin-only and has no test target. Its write order and removal
  are review-only. An augur-vm that writes no `run.id` makes every pass unrecordable (fail closed: the
  boot stops, a running VM is refused), with a reinstall remedy in the message.
- **The comment-tolerant drop-in check.** A comment line is ignored by sshd too, so tolerating it adds
  nothing sshd would act on; any other directive is still refused.
- Carried unchanged from 2026-11-08: host-side process-env visibility (unobserved on a Mac),
  host-env-sourced values already in augur's environment, old credential bytes in a clone's free blocks,
  and the dependency on the guest git helper-chain reset.
