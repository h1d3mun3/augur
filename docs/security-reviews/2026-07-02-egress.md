## 1. Essence

augur egress control is a **host-side, fail-closed, on-by-default domain allowlist** that confines a possibly prompt-injected coding agent (Claude Code today), running on a trusted single-user host, by forcing *all* guest outbound traffic through **augur-proxy** — a dependency-free Swift forward proxy that runs as the ordinary host user **with no sudo**. The guest is placed on an `--internal` network with `NET_ADMIN` dropped and external DNS killed, so its only route out is the proxy, which re-resolves each connection **by hostname** and admits it only if it matches a **union-only, three-layer domain allowlist** (managed baseline + user-global + per-project); everything else is denied and logged. Egress is on by default (`AUGUR_EGRESS=auto`), unrecognized values fail *on*, and the same allowlist/enforcement contract is shared across all three engines. The core design principle is **containment, not exfiltration-proofing**: keep an untrusted agent away from arbitrary internet endpoints and off the host, using only mechanisms that never require elevated privilege.

## 2. Enforcement boundary per engine

All three engines share the *same* merged allowlist and the *same* augur-proxy filter core; they differ only in **where the proxy runs** and **how the guest is severed from direct egress**.

| Engine | Proxy placement | Guest containment | Strength | Specific weakness |
|---|---|---|---|---|

Also puts secrets on `docker run` argv (M1, accepted). |
| **Apple Container (host-only)** | augur-proxy runs **on the host**, bound to the **host-only gateway IP** (not `0.0.0.0`), started *after* the container attaches | Apple `--internal` is **host-only** (internet severed, host reachable); `--cap-drop NET_ADMIN`, `--no-dns` (empty resolv.conf), `HTTP(S)_PROXY`→gateway IP | Sudo-free equivalent of the sidecar for the primary engine; `--no-dns` confirmed live on macOS 26 (c28a3b1); gateway-bind keeps the proxy off the LAN (62a35a9) | **Host-only lets the guest reach other host services bound to `0.0.0.0`** — strictly weaker than Docker's isolated sidecar network. ## 3. augur-proxy filter internals

Dependency-free, cross-platform SwiftPM package — POSIX sockets only, no third-party deps. Two listeners over one shared allowlist: an HTTP CONNECT/forward-proxy (Docker datapath) and a SOCKS5 server (macOS/gvproxy datapath).

- **Fail-closed startup** (`main.swift`): requires a non-empty `--allowlist` and at least one of `--http-port`/`--socks-port`; **`die`/`exit(2)` if the allowlist file is unreadable** — it refuses to start without a readable policy. Flags: `--allowlist`, `--listen` (default `127.0.0.1`), `--http-port`, `--socks-port`, `--log`, `--pidfile`, `--allow-private` (sets `publicOnly=false`), plus `--max-connections` / `AUGUR_PROXY_MAX_CONNECTIONS` (default 128, **undocumented in the README**).
- **Allowlist matching (boundary-anchored)** (`Allowlist.swift`): `*.x`→subdomains only, `.x`→apex + subdomains, bare `x`→apex only. `allows()` lowercases, strips port + one trailing dot, **rejects IP literals and any host failing `isValidHostname`**, then checks exact membership else `isSubdomain`. `isSubdomain` requires a `.` at the label boundary — so `*.github.com` matches `api.github.com` but **not** `evilgithub.com` or `github.com.evil.com` (tested).
- **Hostname validation (NUL-truncation guard)** (`Hostname.swift`): strict LDH on UTF-8 bytes, ≤253 total, per-label 1–63, rejects empty labels and NUL/space/underscore. Prevents `evil.com\0.github.com` matching the list yet dialing `evil.com`. Mirrored by the shell's `conf_line_valid` grammar.
- **HTTP CONNECT vs SOCKS5**: HTTP parses `CONNECT host:port` or absolute-form and dials upstream **by name**. SOCKS5 (no-auth, CONNECT only) receives IP-literal requests from gvproxy, so it **peeks SNI/Host and re-dials by name** (re-resolving) — a spoofed SNI can't exfil elsewhere.
- **DNS pin table (scaffold — unwired)** (`Filter.swift`, `PinTable.swift`): a thread-safe per-client `IP → {domain,expiry}` table that would re-allow an IP literal mapped to a still-allowed name. It is **fully implemented and unit-tested but has no production caller** (no in-process filtering DNS resolver; `pin()` is never invoked), so at runtime **every IP-literal connect is denied unconditionally** — the intended fail-secure state.
- **Hot reload (never falls open)** (`main.swift`): a background thread polls the allowlist mtime every 2s; a successful parse (even empty = deny-all) is applied atomically under `NSLock`; an **unreadable file keeps the previous policy**. Reload never widens mid-request.
- **Dial-time SSRF guard** (`SocketIO.swift` + `AddressPolicy`): under `publicOnly` (the production default), `Sock.connect` **skips any resolved address classified non-public** (loopback, RFC1918, CGNAT, link-local, ULA, multicast, IPv4-mapped v6, NAT64, metadata `169.254.169.254`); unknown family refused. Applied to the same `getaddrinfo` result used to connect. augur never passes `--allow-private` on a production path.
- **Deny logging** (`Logger.swift`): one greppable `DENY client=… dst=host:port reason=…` line per block (`not-in-allowlist`, `ip-literal`, `no-sni`, `upstream-unreachable`) to file + stderr; ALLOW lines are stderr-only.

## 4. Three-layer allowlist config model + TOFU

**Three layers, union-only merge** — each layer can *widen*, none can remove a lower layer's entries:

1. **Managed baseline** `~/.augur/augur.conf.default` — copied verbatim from repo `augur.conf` on **every install**.
2. **User global** `~/.augur/augur.conf` — scaffolded once, **never clobbered**.
3. **Per-project** `./.augur.conf` — merged **sanitized only** (via `project_conf_domains` / `conf_line_valid`).

`write_merged_allowlist` cats baseline + global **verbatim**, then appends only sanitized project domains, and writes to `~/.augur/proxy/<slug>.allowlist` **outside the project mount** — so a root-in-guest editing the mounted `./.augur.conf` **cannot widen its own policy mid-session** (invariant I7).

**TOFU approval** (`check_project_conf_approved`): the project conf is fingerprinted (`sha256sum`/`shasum`; **fails closed if no hash tool**). New/changed → print the sanitized widening domains and prompt `[y/N]`; declined or non-interactive without `AUGUR_ACCEPT_PROJECT_CONF=1` → **exit 1 (fail closed)**. Approvals are stored host-side at `~/.augur/project-hashes/<slug>-<12-hex sha256 of full workspace path>`, keyed on the **full path** so a hostile same-basename repo can't inherit another project's approval, and never mounted so the guest can't forge it.

**Grammar** (honored identically by shell `conf_line_valid` and Swift `Allowlist`): `example.com` = apex only, `*.example.com` = subdomains only, `.example.com` = apex + subdomains.

**Current default baseline set — 18 patterns** (`augur.conf`):
- **Claude Code runtime**: `api.anthropic.com`, `.claude.ai`, `.claude.com`, `*.anthropic.com`, `statsig.anthropic.com`, `statsig.com`, `*.statsig.com`, `sentry.io`, `*.sentry.io`
- **GitHub**: `github.com`, `api.github.com`, `codeload.github.com`, `objects.githubusercontent.com`, `raw.githubusercontent.com`, `*.githubusercontent.com`
- **Homebrew/ghcr (macOS VM mode)**: `formulae.brew.sh`, `ghcr.io`, `*.ghcr.io`

`registry.npmjs.org` was dropped (PR #57 — the Swift image ships no node/npm); `.claude.ai`/`.claude.com` were broadened from apex-only. The baseline block is tagged `AUGUR_AGENT_SEAM` as the swappable per-agent surface, but there is **deliberately no agent-selection mechanism yet** — Claude Code is the only agent; per-agent baselines are design-only.

## 6. Known limitations & residual exfil channels

The threat model is *"contain a prompt-injected agent away from its host,"* **not** *prevent exfil through a legitimately allowlisted, credentialed host*.

1. **Allowlisted + credentialed host is an in-policy exfil surface.** `github.com` is allowlisted and a full-scope `GH_TOKEN` is injected → an injected agent can push data to an attacker-controlled repo entirely within policy. augur does not attempt to stop this.
2. **Wildcard / QNAME tunneling.** A broad wildcard (e.g. `*.githubusercontent.com`) permits `<data>.<wildcard>` leakage; mitigation is **allowlist policy, not the matcher**.
3. **Apple Container `0.0.0.0` host-reach (the accepted trade-off).** Host-only `--internal` lets the guest reach other host services bound to `0.0.0.0` — weaker than Docker's isolated sidecar network. A direct consequence of the **no-sudo constraint** (closing it needs host `pf` = sudo, which augur refuses), so it is documented, not enforced. Given the hard no-sudo rule, this is effectively **permanent**. (Distinct from the *inbound* LAN exposure already fixed by the gateway-bind commit 62a35a9.)
4. **No-sudo consequences ripple through the datapath.** "Never require sudo" took priority over stronger isolation, ruling out macOS `pf` and forcing host-only + host-side proxy (Apple) and `VZFileHandle` + gvproxy SOCKS (VM).
5. **TOFU auto-accept widens non-interactively.** `AUGUR_ACCEPT_PROJECT_CONF=1` widens egress without operator review (used by CI).
6. **Credentials on Docker argv (M1).** Accepted Low under the single-user premise; **resurfaces on a shared host**.
7. **Basename-only slug collisions (~1/900).** Approval-hash and history dirs are full-path-keyed, but container/VM names and egress ports/subnet remain basename-keyed, so two same-basename projects running concurrently still collide on ports and subnet; recovery is a manual `AUGUR_INTERNAL_SUBNET`/`AUGUR_SIDECAR_IP` override.
8. **Every "accepted" residual assumes a single-user host.** On a shared host / CI runner, the argv secret exposure, name collisions, and cross-tenant reach all resurface.
9. **Fail-closed edges are hard errors, not graceful.** Proxy readiness is a fixed ~2s poll and gateway-iface readiness waits ≤5s; on slow bring-up the bind can still fail and `exit 1` (fails closed, but hard).
10. **Compatibility limits (fail-closed).** Connections with no recoverable SNI/Host (ECH/ESNI, non-TLS/non-HTTP) are denied; IPv6/IP-literal connects fail closed. augur's egress needs are all HTTPS, so this is accepted.
11. **Remaining stale docs.** The top-level `README.md` / `install` still mention `npm` in the baseline description though `registry.npmjs.org` was dropped. (The `augur-proxy/README.md` `host.docker.internal` line was fixed in PR #66.)

### Summary
Egress control is a **host-side, fail-closed, sudo-free domain-allowlist scheme shared by all 3 engines**, on by default, with a union-only three-layer merge, TOFU approval, and a Swift filter core (boundary matching, NUL defense, SNI re-decision, unconditional IP-literal deny, SSRF guard, non-fail-open hot reload). As of this snapshot, **invariants I1–I8 are test-enforced and Docker egress containment is gated in CI** — the two biggest gaps the 2026-06-30 snapshot flagged. The remaining intentional residual surfaces are the **Apple host-only `0.0.0.0` reach** (permanent under no-sudo), **in-policy exfil via an allowlisted credentialed host**, and the **macOS-engine containment lacking any CI gate** (validated manually on Apple Silicon only). The only active unmerged work is the local-LLM (Ollama) support on `feature/ollama-llm-endpoint`.
